### 团队发现的最重要问题（已由 Lead 修复）

**严重 · 静默假成功**：LLM 回复里若先出现占位的 `{}` 或 `{ ... }`（模型解释格式时很常见），
抽取器会把它当成结果 → 合并出 0 个角色 → 但引擎记为「成功」→
界面显示「完成：新增 0 个…失败 0 个」，日志空白，用户以为跑完了。
**已修**：抽取器跳过空容器候选；引擎增加「零产出即失败」判定，走重试/失败记录。

另外修复的中等问题：中止标志失真（把「取消」显示成「完成」）、A1111 参数切分不感知引号、
智绘姬 rename 时服装键不跟随改名（新外观串到旧角色）、overwrite 全量替换丢插件私有字段、
存档校验失败静默丢弃用户全部自建预设、降级路径把重试预算放大到 `(batch+1)×(retries+1)` 次、
ComfyUI 把负向提示词混进角色 DNA、智绘姬数组入参把下标当角色名、id 冲突时无上限循环。

## 5. 已知限制（不阻塞使用，已如实记录）

1. **跨域被拦的图**拿不到元数据 → 用界面的「上传」按钮选本地 PNG（一定成功），或填「图床代理前缀」。
2. **图库发现依赖状态栏脚本**：内置 20+ 角色靠 `getScriptTrees` 找到名为「状态栏」的脚本；
   若没装/没启用该脚本，只会有创意工坊角色 —— 界面会给出 warning，也可手动粘 URL 补。
3. **世界书只实现了单条目模式**：`entry_mode` 的 grouped/auto 尚未接线，产出汇成一个蓝灯条目（即「全角色蓝灯精简」形态）。
4. **元数据缓存未实现**：`settings.cache_limit` 字段暂时无用。
5. 审查报告里的 15 条「轻微」项尚未全部处理（多为容错边界与注释口径），清单在 `reports/代码审查.md`。
