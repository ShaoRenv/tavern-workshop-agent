## 0. 置信度分级体系（全手册适用）

> **收集日期统一声明**：本手册全部条目收集于 **2026-06-27**，交叉验证跨 6 个独立来源。源码级断言的回源核实基于本地 SillyTavern **v1.14.0**（`world-info.js` 等）；手册中标注的 commit/sha（如 5e68410、staging）为**采集时快照**，与本地 v1.14.0 机制一致但行号可能漂移。

每条结论采用 **置信度等级 + 依据类型** 双轴标注。

### ① 置信度三级

| 级别 | 含义 | 判定标准 |
|---|---|---|
| **high** | 已坐实，可直接施工 | 有运行时证据（真机实测 / 读到运行时实现源码 / 生产卡验证）；结论是源码/文档的**直接事实**而非下游推导；不在悬案清单 |
| **medium** | 待验证，施工前须实测 | 强制二选一子标签：`medium·单源孤证`（单一来源、无第二源、无实测）/ `medium·推导未验证`（源码或逻辑推导成立但未跑通，**须随附真机验证路径**）|
| **low** | 孤证无源，禁止据此施工 | 零来源猜测 / 纯历史快照（须标年份 + 窄缩适用范围）|

### ② 依据类型标签（与置信度正交，强制标注）

`[运行时源码]`、`[真机]`、`[文档·多源]`、`[文档·单源]`、`[历史孤证:年份]`、`[无源·待考]`

### ③ 两条铁规

1. **「从源码事实再推一步」的下游推导（如 sort→注入位置、splice→reverse→落位、getScore→激活门槛），即使源码本身已直读，该推导结论最高只能 `medium·推导未验证`**——除非已真机验证；源码内部事实仍标 `high [运行时源码]`。
2. **节级标注 = 节内条目下确界**——禁止整节标 high 却内含悬案条目；冲突即在节内局部降级（**§7.1 是正面范例**）。正文断言凡命中悬案章（本手册 §21 U 系列）的，置信度不得高于该悬案对应级别，并交叉引用。

## 2. 条目字段完整参考

### 2.1 核心字段速查表

| 字段 | 类型 | 说明 | 默认值 |
|---|---|---|---|
| `key` | 逗号分隔字符串 / regex 列表 | 主关键词 | 空 |
| `keysecondary` | 逗号分隔字符串 / regex 列表 | 次级关键词（Optional Filter） | 空 |
| `selective` | bool | 是否启用次级关键词逻辑 | false |

| `content` | string | 注入内容（支持宏） | 空 |
| `constant` | bool | 是否为 Constant（蓝圈，无需关键词） | false |
| `disable` | bool | 是否禁用 | false |
| `order` | int | Insertion Order，影响注入位置 | 100 |
| `group` | string | Inclusion Group 标签（逗号分隔支持多组） | 空 |
| `groupOverride` | bool | Prioritize Inclusion（最高 order 确定性胜出） | false |
| `groupWeight` | int | Group Weight（加权随机权重） | 100 |
| `useGroupScoring` | bool | 是否启用 Group Scoring（条目级） | false |
| `probability` | int 0-100 | 触发百分比 | 100 |
| `scanDepth` | int / null | 条目级扫描深度覆盖 | null（继承全局） |
| `caseSensitive` | bool / null | 大小写敏感覆盖 | null（继承全局） |
| `matchWholeWords` | bool / null | 全词匹配覆盖 | null（继承全局） |
| `vectorized` | bool | 允许向量激活 | false |

| `role` | 0/1/2 | atDepth 角色（0=system,1=user,2=assistant） | 0 |
| `sticky` | int | Sticky 消息数 | 0 |
| `cooldown` | int | Cooldown 消息数 | 0 |
| `delay` | int | Delay 最小消息数 | 0 |

## 20. 工程实践与范式代码

### 20.1 随机事件（低概率 Probability）

```
Key: 长老神名字
Content: 长老神被唤醒，开始干预当前场景...
Probability: 1
Strategy: 🟢
```

每次关键词命中时有 1% 概率插入，实现随机事件触发。

### 20.2 Inclusion Group 回退序列

```
Entry_Specific: keys=[common_key, specific_key], group=scene_pool
  order=200, groupOverride=ON (Prioritize Inclusion)
Entry_Default:  keys=[common_key],               group=scene_pool
  order=100, groupOverride=ON

→ specific_key 也出现时：Entry_Specific (order=200) 确定性胜出
→ 只有 common_key 时：Entry_Default (order=100) 胜出
```

### 20.3 Sticky + Cooldown 状态机

```
Entry: 战斗状态
Keys: 攻击, 战斗, 开战
sticky=5 cooldown=3 delay=0
Content: [当前处于战斗状态的规则...]

→ 战斗触发后保持 5 条消息，结束后 3 条消息冷却防重复激活
```

### 20.4 递归链配置

```json
{"key": ["贝西"], "content": "贝西是奶牛，鲁弗斯的朋友", "prevent_recursion": false},
{"key": ["鲁弗斯"], "content": "鲁弗斯是狗，住老农场", "prevent_recursion": false},
{"key": ["老农场"], "content": "老农场坐落于...", "delay_until_recursion": true}
```

### 20.6 扩展插件注入深度 prompt（IN_CHAT）

```javascript
import { setExtensionPrompt, extension_prompt_types, extension_prompt_roles } from '../../../script.js';

setExtensionPrompt(
  'MY_EXTENSION_KEY',
  '注入内容',
  extension_prompt_types.IN_CHAT,  // 1
  2,                               // depth=2
  false,                           // 不参与 WI 关键词扫描
  extension_prompt_roles.SYSTEM    // 0=system
);
```
