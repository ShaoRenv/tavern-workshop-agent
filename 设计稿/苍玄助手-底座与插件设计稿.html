苍玄助手 · 底座 + 插件 · 前端设计

底座 = 选预设 → 跑一轮 → 看结果。工具 / 技能 / 页面 / 宏 = 四张注册表；插件还能声明设置字段，由宿主渲染

屏 1 / 边界：底座做四件事，其余全是插件

底座（永不插件化）
① 跑一轮→ ② 接口→ ③ 预设 / 技能→ ④ 装载 / 存储

① 对话循环 · 工具调用 · 停止 · 轮次与运行状态（● 运行中 · 第 N 轮）
② 模型接口（自填 / 酒馆）· 多模态 · 超时
③ 预设（items + 特殊层）· 技能（按需加载的知识）· 轮数预算
④ 四张注册表（工具 / 技能 / 页面 / 宏）+ 脚本变量存储 · 导入导出

四张注册表 + 一样声明
工具注册表底座自带工具 / 内置插件 / 外部插件 / MCP（远端工具，运行时注册）
技能库用户自己写 + 插件自带（contributes.skills）
页面注册表核心页（对话 / 设置）+ 插件页（inTabbar / order）
宏注册表底座自己的宏（用户需求 / 世界书 / 产物…）+ 插件贡献的宏（图片提示词）；宏不单独占管理段，来源在插件管理页看得见
设置字段插件声明、宿主渲染 —— 不是第四张表，是「这个插件长什么样」的声明

判据（三句话）
1. 没有它，agent 还跑不跑得起来一轮？跑不起来 → 底座
2. 它是某个内容 / 场景专有的吗？→ 插件
3. 关掉它，用户还有没有「助手」？没了 → 底座；只是少个功能 → 插件

MCP 不是「网络工具」这一类功能工具，而是「工具来源」：把远端 server 的工具注册进工具表。 跟「翻译插件」那种自己实现工具的不是一类，但都对底座呈现为同一个东西 —— 工具。

宏 = 文本里的占位符（{{名字}}）：它给的是「文本里的一个值」，写在哪就在哪展开（角色卡 / 世界书 / 预设 / 酒馆提示词），所以它既不是工具也不是技能，是第四张表。

贡献分两类：活的（工具 / 页面 / 技能 —— 关掉插件即消失）与 入口（预设模板 —— 点一下导入成你自己的预设，导入后归你，关插件不回收）。

为什么这样划

  • 底座能用一句话说完：选预设 → 跑一轮 → 看结果。说不完说明有东西该搬出去。
  • 常用 ≠ 核心：世界书很常用，但关掉它 agent 照样成立 → 插件（默认开）。
  • 工具 vs 技能是一对原语：工具＝可执行动作，技能＝按需加载的知识。两者都留底座，插件可以"自带"技能。

对话页 = agent 的正面
· 右上角 ⋯ 设置里放记录（这次会话的事件流水：谁说了什么、调了哪个工具、改了什么）→ 点开是一张 Sheet，不占页面也不占格子
· 用户说话 / 附图 · 工具卡一行跑完才折叠
· 出图就在这里显示（插件页不做预览）
· 顶部固定可见：● 运行中 · 第 N 轮

为什么要动顶栏

  • 固定六页签 = 每加一个功能就动界面骨架；注册表驱动之后，页面是插件的产物。
  • 顶栏回答「你在哪」，设置回答「你怎么管」，两者不再混在一栏里。
  • 顶栏只放「你在哪」：能不放的就不放 —— 能力进设置、记录进对话页右上角的 ⋯、苍玄助手（原立绘）干脆不要页面。
  • 时间线：阶段 1 保持现在的 6 格与老顺序（纯等价改写）；阶段 2 砍掉「能力」（进设置）与「记录」（进对话页右上角 ⋯）（→ 4 格：对话 / 苍玄助手 / 世界书 / 设置）；阶段 3 苍玄助手去页面 + 世界书归插件（→ 3 格：对话 / 世界书 / 设置）。上面画的是阶段 3 之后的目标形态。
  • 老数据里 active_tab = records / portraits 会落到对话页（页不存在 → 回落到第一个可用页），不用用户做任何事。

为什么技能不做成插件
· 工具＝可执行动作，技能＝按需加载的知识，两者都是「模型能请求的东西」，是底座的一对原语
· 工具的实现天然来自插件（工具就是插件代码）；技能的内容通常是用户自己的知识，不属于任何插件 → 库必须留底座
· 插件化技能会让"知识"这个概念散到每个插件里，没有统一入口

这一屏的要点

  • 技能库是底座管理面，不占顶栏（跟工具/插件一样收进设置）。
  • 技能行上标来源：「自己写的」/「苍玄助手自带」—— 跟工具来源标签同一套口径。
  • contributes.skills 是插件自带知识的唯一入口（第 3 阶段落地）。

每个服务器单独开关。它拉来的工具会出现在「设置 · 能力 · 工具」里，来源标 MCP · 服务器名。
工具的逐条停用在这里勾（存插件自己的设置 servers[].disabled_tools）；「工具」段只读，不放开关键 —— 停用永远在来源处。

实话
· 第一期只做 HTTP / SSE：浏览器里生不出进程，stdio 型 MCP 需要本机小桥（二期）
· 远端工具的描述会进提示词、调用会真的执行 → 界面标「来自远端」+ 逐条可停用，不做门禁（既定原则）
· MCP 排在「外部插件装载（URL / 粘贴 JS）」之前做：它不加载别人的代码，风险小一个数量级

为什么 MCP 是个插件

  • 底座只有「工具」一个概念；MCP 只是把远端声明的工具注册进来 → 底座一行都不用改。
  • 插件名一律不带「插件」后缀（列表里每行都是插件）：苍玄助手 / 世界书 / 生图 / MCP。
  • 三件套映射：tools → 工具注册表；resources → 先当只读工具；prompts → 提示词块（二期）。
  • 服务器页 = 它的工具清单（逐条可停用），跟「工具」段是同一份数据、两个视角。
  • 工具是「运行时注册」的：连上以后才 tools/list -> 逐个 upsert 进工具注册表，断开就撤销。底座因此完全不知道「MCP」这个词 —— 静态清单（manifest.tools）之外再开一条运行时通道，就够。
  • MCP 内容页默认 inTabbar: false（从 设置 · 能力 · 插件 -> MCP -> 它加了什么 -> 页面 进）；想常驻顶栏就把它的 order 提前。

屏 8 / 四张注册表与插件契约（前端适配的落点）

页面定义

PluginPage

id 页面 id（跟老页签 id 一致 → 零迁移）
title 顶栏显示名
order 排序（核心页 10/20/…，插件页往后排）
inTabbar 上不上顶栏（false = 从插件管理页进）

MacroDef（第四张表）

key 宏名（图片提示词，不带花括号）
scopes 在哪生效：tavern（酒馆宏，角色卡 / 世界书 / 酒馆预设都能用）· preset（苍玄助手预设 items）
resolve(ctx) 取值函数；注册 / 注销由底座做（插件只给 resolve）
关掉插件 → 宏立刻注销（写着的 {{图片提示词}} 退回空串）
核心页只有两个
对话（记录在它右上角 ⋯ 里的 Sheet）· 设置 —— 其余全是插件贡献的页面（现在只有世界书）。
前端适配清单（对着现有代码）
core/pages.ts（新）核心页定义：对话 / 设置 + 页面合并函数。记录不在这里 —— 它是对话页里的一张 Sheet
core/types.tsTAB_IDS / TabId 删掉（页面 id 只在注册表里定义一份）；active_tab 放宽成 string；新增 plugin_state；别名 records / portraits → chat

stores/app.tssetTab(id: string) + 存在性校验；setPluginEnabled；关插件时当前页被撤 → 自动回落
三条硬要求
1. 一个脚本 = 一个文件：苍玄助手在酒馆里是一整段 JS，import() 拆出的 chunk 没人能加载 → 阶段 1-3 一律静态 import，阶段 3 加 limitChunkCount = 1；懒加载留给二期外部插件（那时才有独立 URL）。验收看「产物里不出现 chunk 请求」
2. 页面取数契约：插件页只拿 host + 自己插件的设置（host.config），不许直接 import store
3. 运行状态归宿主：● 运行中 · 第 N 轮 / 输入框 / 通知条由 AppShell 统一画
4. 页面级错误边界：插件页抛错只挂它自己 —— 页内显示「这个插件挂了」+ 一个停用按钮，不许把整个面板带下去
插件契约（最小形态）
interface PluginManifest { id; name; version; apiVersion: 1; desc; builtin; defaultEnabled; contributes: { pages?: PluginPage[]; // { id, title, order, inTabbar }（可以一个都不要 —— 苍玄助手就没有） tools?: string[]; // 阶段 1 = 工具名；阶段 3 起 = ToolDef（字段名、形状都只一种） macros?: MacroDef[]; // 宏：{ key, scopes, resolve }，注册 / 注销由底座做 skills?: Skill[]; // 自带知识：随插件开关 presets?: PresetTemplate[];// 入口：点一下导入成用户的预设，关插件不回收 settings?: SettingsField[];// 第 4 阶段起：声明字段，宿主渲染 }; status?(config): { label; kind }; // 插件自己算状态（未启用 / 出错 / 缺配置 / 已启用） } // 运行时通道（MCP 这类）：registerRuntimeTools(pluginId, ToolDef[])，断开即撤销 // contributes.prompts（提示词块）已从这一版删掉 —— 没有消费者，跟钩子总线一起放二期

两条硬规矩：插件只拿得到 host（不许互相 import）；活的贡献（工具 / 页面 / 技能）必须「关掉即消失」。

屏 9 / 落地顺序（每步可单独验收）
