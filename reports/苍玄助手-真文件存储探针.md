# 苍玄助手 · S0 真文件存储探针报告

> 时间：2026-09-21 · 方式：真酒馆（`C:\SillyTavern-1.18.0`，端口 8000，PID 37424）+ 面板 iframe 内实测
> 结论一句话：**「文件不好存」在脚本形态下已经解决** —— 面板 iframe 可直接调 ST 原生上传接口，拿到可持久、可渲染、可删除的 URL，**零迁移**。

## 1. 为什么做这个探针

用户原话：「感觉脚本上限太低了，文件什么的都不好存储」。

磁盘实测否定了前半句、确认了后半句：

| 事实 | 数值 |
|---|---|
| `data/default-user/settings.json` | **51563 KB ≈ 50.4MB** |
| 其中 `extension_settings` | **25.1MB** |
| ├ `st-chatu8` | 15.08MB |
| └ `tavern_helper`（`script.scripts[]`，10 个脚本） | 9.49MB |
| 我们的开发版脚本 | **1KB**（生产版 543KB 压根没装进酒馆） |
| `__userscripts` | 0.39MB |
| `base64_image_literals` | 9 |

**撑爆 settings.json 的不是我们的脚本**，是别的脚本把 base64 图片直接塞进变量。真正的痛点是「素材没地方存」，而不是「脚本能力不够」。

ST 原生上传接口在脚本形态下**本来就能用**，只是我们没接。

## 2. 接口契约（源码实证，非猜测）

### 2.1 上传图片 `POST /api/images/upload`

依据 `C:\SillyTavern-1.18.0\src\endpoints\images.js:39-78`：

```js
// 请求体
{ image: '<base64 无前缀>', format: 'png', filename?: 'cx-s0-asset', ch_name?: 'cx-assets' }
// 响应
{ path: '/user/images/cx-assets/cx-s0-asset.png' }   // client-relative
```

- `format` 必须在 `MEDIA_EXTENSIONS` 里，否则 400；
- `filename` 省略时用 `Date.now()`；
- `ch_name` 是**子目录**（实测可当插件的私有素材夹用）；
- 返回的是 **client-relative 路径**，直接拼在酒馆 origin 后就是一个可用 URL。

### 2.2 列目录 `POST /api/images/list` / `POST /api/images/folders`

依据 `images.js:80-131`：`list` 要 `{folder}`（目录不存在会自动建），`folders` 无参返回子目录名数组。

### 2.3 删除 `POST /api/images/delete`

依据 `images.js:133-155`：`{ path }`，且**必须落在 userImages 目录下**（`isPathUnderParent` 越界即 400）。

### 2.4 通用文件 `POST /api/files/upload` / `delete` / `verify`

依据 `src/endpoints/files.js:28-101`：

```js
// upload: { name: 'x.json', data: '<base64>' } -> { path: '/user/files/x.json' }
// delete: { path }        // 必须落在 directories.files 下
// verify: { urls: [...] } -> { '/user/files/x.json': true }
```

`files` 目录**没有子目录参数**，只能平铺；`images` 才有 `ch_name` 分目录。

### 2.5 ⚠️ 关键前置：CSRF

裸 POST 直接 **403**（第一次探测就是这个结果）。依据 `src/server-main.js:166-202`：

- 默认开启 `csrf-sync`；token 从 `GET /csrf-token` 拿（返回 `{token}`，长 64 字符）；
- 请求要带 **`X-CSRF-Token` 头**（`server-main.js:176-178` 读的就是这个小写头的 `.toString()`）；
- 必须 `credentials: 'include'` 带上会话 cookie，否则 `req.session` 无 token。

## 3. 实测结果（全部在真酒馆上跑）

### 3.1 从面板 iframe 上传（决定性一测）

`cx-pw-frame` 面板 iframe 的运行环境实测：

| 项 | 实测值 |
|---|---|
| 面板 iframe | `id=cx-pw-frame`，`location=about:srcdoc` |
| 同源 | **是**（可读 `contentDocument`，即与酒馆同源） |
| 面板内 `window.TavernHelper` | `false`（面板自己拿不到，但**不需要**它） |
| 面板内 `fetch('/csrf-token')` | **200，token 长 64** |
| 面板内 `POST /api/images/upload` | **200** → `{"path":"/user/images/cx-assets/cx-from-panel.png"}` |
| 该 URL 当 `<img src>` | **onload 成功**，`naturalWidth=1 / naturalHeight=1` |

**结论：面板 iframe 与酒馆同源，带 `credentials:'include'` + `X-CSRF-Token` 就能直接上传，完全绕开 `TavernHelper`。**

### 3.2 完整生命周期

| 步骤 | 请求 | 结果 |
|---|---|---|
| 上传到插件私有夹 | `POST /api/images/upload` `{ch_name:'cx-assets'}` | 200 → `/user/images/cx-assets/cx-s0-asset.png` |
| 当 URL 取回 | `GET /user/images/cx-assets/cx-s0-asset.png` | **200**，`content-type: image/png`，70 bytes |
| 列子目录 | `POST /api/images/folders` | 200 → `["chatu8","chatu8List","chatu8_config","cx-assets","destined","大渊习武录","恶堕方舟（持续更新中）","柏宝绘_恶堕方舟（持续更新中）","苍玄界"]` |
| 列文件 | `POST /api/images/list` `{folder:'cx-assets'}` | 200 → `["cx-s0-asset.png"]` |
| 大文件 | 1125KB base64 上传 | **200，29ms** |
| 删除 | `POST /api/images/delete` `{path}` | **200 OK** |

| **跨刷新** | 整页 reload 后重新 GET | **200**，`image/png`，70 bytes |

### 3.3 与用户现有素材的关系

`cx-assets` 与用户已有的 **`苍玄界`** 目录并列出现在 folders 列表里 —— 说明插件素材夹能自然融入用户现有素材体系，不需要另起存储。

## 4. 结论

1. **「文件不好存」已解决**：立绘 / 素材可以上传成真文件，存 **URL**（几十字节）而不是 base64（几十 MB）；
2. **零迁移**：不用换扩展、不用改架构、不加数据键；存量只存 URL，落在 `plugins.cangxuan`；
3. **面板直接可用**：`about:srcdoc` 同源 iframe，`fetch` + CSRF 头即可，**不依赖 `TavernHelper`**；
4. **两条存储分工清楚**：
   - `images`（有 `ch_name` 子目录）→ 立绘 / 素材库；
   - `files`（平铺）→ 插件包 / JSON 导出；
5. S0 **不动 292/292 基线**，是纯增量。

## 5. 可直接复用的代码（写进阶段 3 的 cangxuan 插件）

```ts
// plugins/builtin/cangxuan/assets.ts —— 零依赖，纯 fetch
let csrfToken: string | null = null;

async function getCsrfToken(): Promise<string> {
  if (csrfToken) return csrfToken;
  const r = await fetch('/csrf-token', { credentials: 'include' });
  const j = await r.json();
  csrfToken = j.token as string;
  return csrfToken;
}

async function stPost(url: string, body: unknown): Promise<unknown> {
  const token = await getCsrfToken();
  const r = await fetch(url, {
    method: 'POST',
    credentials: 'include',
    headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': token },
    body: JSON.stringify(body),
  });
  if (r.status === 403) { csrfToken = null; throw new Error('CSRF 失效，刷新页面重试'); }
  if (!r.ok) throw new Error(`上传失败 ${r.status}`);
  return r.json();
}

/** 上传一张立绘，返回可直接当 <img src> 的 URL */
export async function uploadAsset(base64: string, format: string, name: string) {
  const { path } = await stPost('/api/images/upload', {
    image: base64, format, filename: name, ch_name: 'cx-assets',
  }) as { path: string };
  return path;
}

export async function deleteAsset(path: string) {
  return stPost('/api/images/delete', { path });
}

export async function listAssetFolder() {
  return stPost('/api/images/list', { folder: 'cx-assets' }) as Promise<string[]>;
}
```
