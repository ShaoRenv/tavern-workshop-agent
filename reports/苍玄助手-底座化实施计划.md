# 苍玄助手 · 底座化实施计划（详细）

> 这份文档是**动手改代码时的唯一依据**，也是压缩上下文后的记忆载体。
> 配套：reports/苍玄助手-底座与插件.md（理念 / 契约 / MCP / 技能定位）、设计稿/苍玄助手-底座与插件设计稿.html（前端设计 9 屏）。

## 0. 一句话目标

把苍玄助手从「六个功能页拼在一起」改成 **Agent 底座 + 插件**：底座只回答「选预设 → 跑一轮 → 看结果」，
其余（苍玄界专用的立绘功能、世界书、生图、MCP…）全部做成插件，往底座的四张注册表里贡献东西。

**三条硬规矩（任何阶段都不许破）**

1. 插件只拿得到底座给的 host，**插件之间不许互相 import**；
2. 插件贡献的东西必须「**关掉即消失**」（页面消失、工具不给模型、技能不进提示词）；
3. 界面用「**列表就是列表**」原则：插件列表只有列表，插件管理页只有它自己的设置 + 可点跳转行。

### 2.1 契约（第 1 阶段定死）

    export type PluginId = string;   // cangxuan / worldbook / image / mcp（页面 id 仍是老的 portraits / worldbook → 零迁移）

    export interface PluginPage {
      id: string;         // 页面 id：**跟老页签 id 一致**（portraits / worldbook）→ 零迁移
      title: string;      // 顶栏显示名
      order: number;      // 排序：核心页 10/20/30…，插件页往后排
      inTabbar?: boolean; // 默认 true；false = 不上顶栏，从插件管理页进
    }

    export interface PluginManifest {
      id: PluginId; name: string; desc: string; version: string;
      apiVersion: 1;
      builtin: boolean;        // true = 可关不可卸；false = 可卸
      defaultEnabled: boolean;
      contributes: {
        pages?: PluginPage[];      // **可以一个都不要** —— 苍玄助手（原立绘）就没有页面
        tools?: PluginToolRef[];    // 第 1 阶段：只声明**归谁 + 默不默认给**（实现仍在 agent/registry.ts）
                                  // PluginToolRef = { name, defaultOn? }：defaultOn=false 的工具（世界书的 entry_meta）
                                  // 插件开着也**不默认进全局能力**，要按需在预设里勾
                                    // 第 3 阶段起换成 ToolDef；字段名与形状**只保留一种**，不写联合类型
        macros?: MacroDef[];         // 第 3 阶段起：宏（注册 / 注销由底座做）
        skills?: Skill[];           // 第 3 阶段起：插件自带知识（活的：随开关消失）
        presets?: PresetTemplate[]; // 入口：点一下导入成用户预设，**关插件不回收**
        settings?: SettingsField[]; // 第 4 阶段起：声明式表单（插件声明字段，宿主渲染）
      };
      /** 插件自己算状态（未启用 / 出错 / 缺配置 / 已启用）；底座只负责画 */
      status?(config: unknown): { label: string; kind: '' | 'ok' | 'warn' | 'dang' };
    }

    export interface MacroDef {
      key: string;                       // '图片提示词'（不带花括号）
      desc: string;                      // 界面上给用户看的一句话
      scopes?: ('tavern' | 'preset')[];  // 默认两个都注册
      resolve(ctx: MacroCtx): string | Promise<string>;
    }
    //  - tavern：走酒馆助手的 registerMacroLike → 角色卡 / 世界书 / 酒馆预设里也能用
    //  - preset：进我们自己的宏表 → 只在苍玄助手预设的 items 里展开
    //  - 注册 / 注销由底座在插件启用 / 停用时统一做，插件只给 resolve（不然没人记得 unregister）
    //  - 宏**不单独占管理段**：来源在插件管理页「它加了什么」里看得见，天天要管的开关仍然只有插件那一个

    // 贡献分两类：**活的**（页面 / 工具 / 技能 / 宏 —— 关掉即消失）
    //             **入口**（presets —— 导入后归用户，关插件不回收）
    // contributes.prompts（提示词块）本版**删掉**：没有消费者，跟钩子总线一起进二期。

### 2.2 数据形状

    RootData = {
      version: 5,                                  // ← 从 4 提到 5
      ...现有字段（api / gen / presets / skills / sessions / drafts / artifacts / tool_overrides）,
      plugins: { <id>: <这个插件的设置> },            // 已有；**enabled 从里面搬走**
      plugin_state: { <id>: { enabled: boolean } },  // 新增：所有插件的开关（含内置插件）
    }

plugin_state 缺某个 id = 用 manifest 的 defaultEnabled（苍玄助手 / 世界书 true，生图 / MCP false）。

`plugins.cangxuan` 里放它自己的设置：`gallery`（图库来源）· `meta_rule`（元数据读取规则）· `manual_meta`（按角色的手动元数据，传图得来）。
**顺手修一个老坑**：现在的「传图」结果只存在 App.vue 的内存 ref 里（`manualMeta`），**刷新就没了** —— 搬进 `plugins.cangxuan.manual_meta` 之后才真的存下来。

- `plugin_state` 暂时**只有 enabled**：`installed_at` 是外部装载（二期）才需要的，现在不预埋。
- **开关为什么不留在 plugins.<id> 里**：开关是底座的（谁在跑由底座定），设置是插件的（插件自己的 schema）。
  分开之后插件 schema 永远不用出现 enabled，底座也不用解析插件设置就知道开关状态。
- **DATA_VERSION 只在结构搬迁时涨**（字段搬家 / 改名 / 换类型）；插件以后新增设置字段靠 zod 默认值兜底，**不涨版本**。

| 状态 | 服务器行的状态由插件自己算（manifest.status）：已连接 / 连不上（带上次错误码）/ 缺配置；列表行状态只取一个，优先级 未启用 > 出错 > 缺配置 > 已启用 |
| 页面 | 服务器列表（名字 / 地址 / 状态 / 开关 / 箭头）→ 服务器页 = 它的工具清单（逐条停用勾在这里，存 **plugins.mcp.servers[].disabled_tools**；「设置 · 能力 · 工具」段只读）；内容页默认 inTabbar: false，从插件管理页「它加了什么 → 页面」进 |
| 数据 | plugins.mcp.servers: [{ id, name, url, headers, enabled, disabled_tools }] |
| 分期 | stdio 型不支持（浏览器生不出进程）→ 二期或不做；resources 先当只读工具；prompts 二期 |

**验收**：连一个 HTTP MCP server → 工具出现在「设置 · 能力 · 工具」且能被模型真的调用；断开服务器 → 它的工具从能力里消失；CORS 被挡时给可操作提示（跟生图插件同一套话术）。

**顺序理由**：MCP 让用户扩展能力但**不加载别人的代码**，风险比「外部插件装载」小一个数量级 → 先做 MCP。
