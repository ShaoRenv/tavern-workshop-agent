> ⚠️ **这份是历史文档（底座化之前写的）**，口径已换代：贡献点、契约、host 接口、术语都以
> `reports/苍玄助手-设计自查.md` → `reports/苍玄助手-底座化实施计划.md` → `reports/苍玄助手-底座与插件.md` 为准。
> 本文只有「为什么外部插件可行」这一层论证还有参考价值，**别照着它写代码**（例如它写的四类贡献点现在是 页面/工具/技能/预设模板/设置字段）。

> 起因：用户提出「做成 DSH 那样的理论，外部导入插件，这样潜力就无限了」。
> 结论：**可以做，而且它是「外部工具」的严格超集** —— 工具只是插件能贡献的东西之一。

## 一、DSH 的插件模型 → 我们这边的对应

| DSH 里的东西 | 苍玄助手里的对应 | 现状 |
|---|---|---|
| 插件包（带 manifest） | 一个 ESM 模块：`export default { manifest, setup(ctx) }` | 新建 |
| 插件往 host 注册**工具** | `ctx.tools.register(toolDef)` | 契约里已有 `ExternalToolManifest` 雏形 |
| 服务 / 依赖注入 | `ctx.get('worldbook' \| 'generate' \| 'variables' \| 'storage')` | 新建 |
| 生命周期事件 / hook | `ctx.hooks.on('run:before' \| 'tool:before' \| 'tool:after' \| 'draft:apply')` | 新建 |
| 贡献 UI（命令 / 面板） | `ctx.ui.registerTab()` / `ctx.ui.slot('settings')` | 新建 |
| 声明式配置 | `ctx.settings(fields)` → 复用 `ToolSettingsField` | 契约里已有 |
| 配置热重载 | 停用 / 卸载 / 重新拉取；面板本来就有热重载链路 | 已有雏形 |
| 权限 / 沙箱分级 | `trust: 'full' \| 'isolated'` | 契约里已有 |
| 版本兼容 | `manifest.apiVersion`，host 拒绝不认识的大版本 | 新建 |

## 二、「潜力无限」的实质 = 四类贡献点

1. **工具**：生图、联网搜索、翻译、OCR、TTS、向量检索、任意 HTTP API —— agent 立刻能用，可勾选、可改提示词
2. **页面**：插件能加一个页签（相册 / 素材库 / 语料管理…）→ UI 从「固定六页」变成「可扩展」
3. **钩子**：`run:before` 改系统提示词、`tool:before` / `tool:after` 拦截或改写工具结果、`draft:apply` 落盘前校验 —— **这才是真正能改行为的能力**
4. **资源 + 设置**：插件自带模板 / 范例 / 预设；设置表单由插件声明，主程序不用跟着改

## 三、实话：折在哪（别把话说满）

- **同源**：插件代码跑在酒馆页面里，和你自己的脚本**同权**。浏览器给不了进程级隔离。唯一真隔离 = `sandboxed iframe + <meta CSP connect-src 'none'>`，那一档不能联网、也碰不到 DOM，功能会缩水
- **没有服务端**：DSH 插件能起进程、装 npm 包；我们只能调 HTTP。所以「无限」准确说是 **「网页能做到的都能做」**
- 但这已经足够大：上面四类贡献点全部落在浏览器能力范围内
- 另一个现实约束：**插件代码体积**。脚本变量能不能塞下几百 KB × N 个插件，要实测；所以存储方案要留后路（见第七节）

## 四、契约要改什么（一次改清，别来回动）

- `ExternalToolManifest` → **`PluginManifest`**：工具只是 `contributes.tools` 之一，平级还有 `tabs` / `hooks` / `settings` / `assets`
- `ToolDef` 已经有 `source` / `origin` → 插件工具带 `source: 'plugin'` + `origin: <插件 id>`
- **命名空间**：插件贡献的工具 / 技能 id 前缀 `plug:<pluginId>/`；`tool_overrides`、脚本变量 key、插件存储同理 —— 防撞名，也方便卸载时一次清干净
- **插件存储**：`ctx.storage.scope()` → 脚本变量里 `cx_plugin_<id>` 一段（`export_with` 决定要不要跟着导出）
- **API 版本**：`manifest.apiVersion`（从 `'1'` 起），host 只保证同大版本向后兼容；不认识就直接拒装并说明原因
- **失败隔离**：一个插件 `setup()` 抛错只能弄死它自己（注册过程包 try/catch，注册失败回滚已注册的东西）

## 五、五步落地（每步都能单独验收）

| 步 | 内容 | 验收标准 |
|---|---|---|
| 1 | 插件契约 + 装载器（URL / 粘贴代码 / 本地文件）+ hash + manifest 校验 + 注册表接入 | 一个「加两个工具」的最小插件装得上、能勾选、agent 能调用 |
| 2 | 插件段 UI：列表（来源 / 版本 / hash / 状态）+ 停用 / 卸载 / 重新拉取 | 设置页能管理插件 |
| 3 | 声明式设置表单（`ToolSettingsField` 8 种控件）由宿主渲染 | 插件声明的 API Key 能在界面上填 |
| 4 | 钩子总线（`run:before` / `tool:before` / `tool:after` / `draft:apply`） | 插件能改系统提示词、能拦截工具结果 |
| 5 | 页面贡献点（`ctx.ui.registerTab`）+ 隔离档 | 插件能加一个页签；隔离档能真禁网 |

## 六、安全垫（不变，而且要在第 1 步之前做）

C1 保存前自动备份整本世界书 → C2 记录页一键回滚 → C3 草稿单条撤销。
理由不变：**全权装载下这是唯一退路**；插件越多越要有。

## 七、要用户拍的三件事

1. **插件能不能加页签？** 能 → UI 从固定六页签改成注册表驱动（改动集中在 AppShell + TAB_IDS + 设置页）；不能 → 插件只贡献工具和钩子。
2. **插件代码存哪？**
   - A：脚本变量 —— 导出/导入带得上、跨设备同步；但要实测体积上限，可能拖慢酒馆
   - B：`localStorage` / IndexedDB —— 不涨脚本变量、按设备各存；换设备要重新从 URL 拉
   - C：URL 为准 —— 代码不落地、只记 hash；离线不可用
   - 倾向：**A 为主 + 超阈值转 B / C**，并把这三种在 manifest 里显式声明
3. **第一版范围**：先做「工具 + 设置表单」（能立刻接生图），还是连钩子一起做？

## 八、和已拍板决定的关系

- 「外部工具全权装载、不做权限门禁」→ 不变，插件继承这条
- 「禁网只能靠隔离模式」→ 不变
- 「创意工坊」→ 用户已说是废弃产物，**不做订阅/工坊**，插件来源只有 URL / 粘贴 / 本地文件
- 「脚本 → 扩展重构押后」→ 不变；插件系统在脚本形态里先跑通，将来搬到扩展形态时这套 manifest 契约可以整体复用

## 9.1 口径：插件 = 一份设置 + 它提供的工具

- **插件页**（能力页第三段：工具｜技能｜**插件**）管「怎么连生图服务、默认出什么画」
- **工具段**管「模型看到什么、能不能用」（提示词 / 参数说明 / 超时）
- **两级能力**：插件开着 → 它的工具进「全局能力」；预设里打开「单独启用预设能力」后，才由那份勾选说了算
- 插件关着：工具从全局能力里消失；预设里硬勾了也会直接报「插件没启用」，**一个请求都不发**

## 9.2 页面结构（照工具详情那套固定骨架）

| 块 | 内容 |
|---|---|
| 1 头部 | ← 返回 · 状态（未启用 / 缺 API Key / 缺反代地址 / 已启用）· 名字 + 来源 + 版本 + 「提供 1 个工具」· 启用开关 |
| 2 接口 | 来源（现只有 NovelAI）· API Key（显示/隐藏）· 站点（官网直连 / 反代，选反代才出地址框）· 模型（7 个，带 v3/v4/v4.5/v5 标注） |
| 3 固定提示词 | 固定正面 / 后置固定正面 / 固定负面（都自动增高）· 追加官方质量词（**按模型显示那一串**）· 负面质量预设（重/轻/人像向/不用） |
| 4 生成参数 | 采样方法 · 噪点表 · 步数 · 尺寸预设 + 宽高 · 种子（0=随机）· Prompt Guidance · Guidance Rescale |
| 5 高级 | **按版本给**：v3 给 SMEA / SMEA DYN / 减少伪影；v4 起不给（并说明为什么）；所有版本给多样性；只有 v5 给透明背景 |
| 6 出图 | 一次最多几张（1–4，成本上限）· 试画用的画面描述 · **试画一张**（直连试；图只在这页预览，不进对话、不烧模型 token） |
| 7 提供的工具 | gen_image 一行（显示「模型能用 / 模型用不到」），点它跳到「工具」段那个工具的详情 |
| 8 还没做 | 占位块，明说：氛围参考图 Vibe / 角色参考图 / 提示词替换 / 云端排队 / 多套配置档案 / 其它生图来源 / 出图存进立绘库 |

## 9.3 NovelAI 参数映射（照参考实现，但改了它三个坑）

- 端点 `POST https://image.novelai.net/ai/generate-image`（反代则 `<地址>/ai/generate-image`）
- 顶层 `{ input, model, action:'generate', parameters }`
- **v3**：`sm` / `sm_dyn` / `dynamic_thresholding`(Decrisp) / `qualityToggle`
- **v4+**：`autoSmea` / `v4_prompt` / `v4_negative_prompt` / `characterPrompts` / `inpaintImg2ImgStrength`，**不带** sm 那三个
- **v5**：`params_version=4`、`straight_alpha`、`tag_hint_qt`、`tag_hint_uc_preset`（参考实现里这三个字段被后面重建 body 冲掉了，我们真的发出去）；`ddim_v3` 自动换成 `k_euler_ancestral`
- 质量词按模型给（st-chatu8 的 AQT 表），负面用官方 `ucPreset` 数字（0 重 / 1 轻 / 2 人像 / 3 不用）
- 响应是 **ZIP**：自己解 ZIP 头 + `DecompressionStream('deflate-raw')`，**不引 JSZip**；反代回 JSON `{images:[…]}` 或裸 base64 也认
- **没抄**的三处：`stream:'msgpack'`（它发了却按 zip 解）、`use_new_shared_trial`（它的试用通道）、恒为 false 的 `use_coords` 表达式

## 9.5 要你拍的四件事

1. **形态对不对**：插件单独一段（工具｜技能｜插件）是不是你要的？还是想让插件设置挂在工具详情里？
2. **「插件开着 → 工具进全局能力」这条口径**认不认？（关插件 = 模型完全看不到 gen_image）
3. **参数取舍**：默认我给了 步数 28 / 尺寸 832×1216 / 采样 Euler Ancestral / Guidance 5 / Rescale 0 / 一次最多 1 张。
   要不要按 st-chatu8 的默认（1024×1024 / k_euler / Guidance 10 / rescale 0.18）？
4. **先做哪一块下一步**：氛围参考图（Vibe）？出图存进立绘库（和立绘页联动）？还是先把「一次多张 + 成本估算」做细？
