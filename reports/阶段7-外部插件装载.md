# 阶段 7 · 外部插件装载 —— 交付与真机验收

> 一句话：**外部插件装得进来了**。贴一个 URL 或一段 JS → 存成酒馆真文件 → 动态执行 → 注册进插件表；
> 它的**页面 / 工具 / 宏 / 技能 / 设置**与内置插件同等地生效，**刷新自动重新装载**，卸载时连代码文件一起删。
> 本轮真机又抓出 **3 个只有接上真宿主才暴露的缺陷**（见 §4），其中一个会让整个功能装不上。

## 1. 交付

| 层 | 文件 | 说明 |
|---|---|---|
| 数据 | `core/types.ts` | `ExternalPluginSchema`（id/name/version/api_version/source/origin/code_path/hash/installed_at/last_error）+ `RootData.external_plugins` |
| 通道 | `plugins/registry.ts` | `allManifests()` = 内置 ∪ 外部；`registerExternalManifest` / `unregisterExternalManifest` / `isExternalPlugin`；**所有聚合函数改走 allManifests** |
| 装载 | `plugins/external/loader.ts` | 下载 / 粘贴 → 写真文件 → 动态 import → 校验 → 注册；`loadInstalled`（启动重装）；`uninstallPlugin`；apiVersion 判据；体积上限；失败隔离 |
| 存储 | `core/storage.ts` | `external_plugins` 登记进 `BLOCK_KEYS`（**不登记就刷新即丢**，见 §4.2） |
| 写点 | `stores/app.ts` | `setExternalPlugin` / `setExternalPluginError` / `removeExternalPlugin`（卸载连开关与设置一起清） |
| 接线 | `App.vue` | 三个 handler（URL / 粘贴 / 卸载）+ 启动 `loadExternalPlugins()` + 注册表非响应式的重算信号 |
| 界面 | `views/PluginsView.vue`（ui-shell） | 安装入口（URL / 粘贴）+ 已装列表（状态 / 开关 / 卸载）+ 安全文案；`.cx-ext-*` 纯追加 |
| 测试 | `tests/苍玄助手/external_loader.test.ts`（test-author，26 条） | 九条性质 + 反例自检 |
| 验收工具 | `dev_plugin_sample.mjs` + `dev_plugin_host.mjs` | 一个**示例外部插件包** + 带 CORS 的托管服务器 |

**外部插件包的格式**：一个 JS 模块，`export const manifest = {…}`（或 `export default`），形状与内置 `manifest.ts` 完全一致 —— 阶段 3 定的「插件 = 自包含目录 + 一份 manifest」在这里兑现。

## 2. 契约（下一轮别推翻）

```ts
allManifests()                    // 内置 ∪ 外部：所有聚合函数必须走它
registerExternalManifest(m)       // 幂等（同 id 整份替换）；撞内置 id 被拒；builtin 强制 false
unregisterExternalManifest(id)

installFromUrl(url, deps) / installFromCode(code, meta, deps) → { ok, id?, error?, updated?, manifest?, code_path?, hash? }
loadInstalled(installed, deps)    // 启动重装；每个插件独立 try/catch（失败隔离）
uninstallPlugin(id, codePath, deps)
codePathFor(id) → '/user/files/cx-plugin-<id>.txt'   // ⚠️ 是 .txt，见 §4.1
```

三条关键口径：
1. **代码存真文件、设置里只留路径 + 哈希**（settings.json 已 50MB，不能再塞 JS）；
2. **外部插件的 defaultEnabled 定死为 true**（用户主动装的，默认启用），避免「界面开关 vs 注册表判断」分叉；
3. **失败隔离**：任何一步抛异常只影响这一个插件，原因写进它的 `last_error`，其余照常。

## 4. ⚠️ 真机当场抓到的 3 个缺陷

### 4.1 插件代码**不能存成 `.js`** —— 整个功能装不上
现象：上传返回 **400 `Forbidden file extension.`**。
根因：ST 的 `/api/files/upload` 走 `validateAssetFileName`，拿 `UNSAFE_EXTENSIONS` 挡扩展名，**名单里明确包含 `.js`**（还有 .html/.htm/.php/.exe…，见 ST `src/constants.js:64`）。
修法：存成 **`.txt`**，并把 `importCode` 的主路改成「**读回文本 → blob → import**」（`.txt` 的静态 MIME 是 text/plain，浏览器拒绝当模块执行）。扩展名在这里只影响「ST 允不允许写」。
> 这条**单测永远抓不到**（它不经过真 ST 的校验），只有真机验收会撞上。

### 4.2 新数据块没登记进 `BLOCK_KEYS` —— 刷新即丢
现象：装完一切正常，**刷新一次变成「0 个」**。
根因：`core/storage.ts` 的逐块恢复只认 `BLOCK_KEYS` 里的键，没登记的新块会被丢掉。代码里那句注释（「新块必须登记在这张表里…跟当初冷启动读不到数据是同一类坑」）正是为这个坑写的 —— 这次轮到 `external_plugins`。
修法：登记进去。

### 4.3 装载成功没重算工具目录 —— 界面又少东西
现象：诊断显示 `pluginAll` / `catalog` 里都有 `ext_hello`，而「能力 · 工具」16 行里没有它。
根因：`loadExternalPlugins()` 装完没调 `loadTools()`；外部插件的**静态**工具不在挂载时那份目录里。
修法：装载成功即重算（`if (result.loaded.length) loadTools()`）。
> 与阶段 6 的 4.2（catalog 是封闭名单）是同一族问题：**「模型拿得到、界面列不出来」**。

**另外**：ui-shell 在写界面时提前抓到一个会让整段白屏的坑 —— 对**未注册**的外部插件 id 调 `pluginEnabled()` 会 throw（`pluginManifest` 查不到就抛），而「装载失败」恰恰意味着 manifest 没注册。改用直接读 `plugin_state`。

### ⭐ 验收员抓到的真缺陷：外部插件状态标签**不看能力闸**

  **从不查能力闸**；而内置插件那行走的是 `pluginStatusWithCapabilities`。
- 复核结论：**成立**，而且是我本轮**自己引入的分叉** —— 我在 `registry.ts` 里让外部插件**同样过能力闸**
  （`pluginCapabilitySkips` 走 `allManifests`），却忘了界面这一侧。
- 后果：一个声明了本机不具备的必需能力的外部包会被拦下（页面 / 工具 / 宏全不出），**界面却显示「已启用」**。

- **真机复验**：贴一个 `requires: ['cx_no_such_capability']` 的包 → 列表显示
  `缺能力探针插件 | v1.0 | **缺能力** | 粘贴的代码`，而正常的包仍显示「已启用」。✅
