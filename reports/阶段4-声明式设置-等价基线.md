# 阶段 4 · 声明式设置：等价基线（Lead 独立产出）

> **这份文件的存在理由**：阶段 4 的验收原文是「生图插件的管理页不再出现任何手写表单代码」。
> 但「不再手写」有个**致命的失败模式**：改写时**漏掉一个控件** —— 界面看起来完全正常，
> 只是用户从此改不了某一项，而且**没有任何报错**。所以改写前后必须有一份逐字段的等价清单来对照。
>
> 这份清单由 **Lead** 在改写**之前**从旧代码里逐行抄下来（不是改写后回填的），
> 只读验收时用它做 diff，不看改写者的自述。

**改写后逐行核对：每行的「可编辑性」必须一致。**

| # | 键 | 旧控件 | 旧属性 | 声明式应表达为 |

| 24 | `max_count` | number | `min=1 max=4 step=1` | `type:'number'` |

**「尺寸」那个复合控件（第 14/15 行的来源）**：旧界面是**一个 select 读两个键、又写两个键** ——
```ts
const sizePick = computed({
  get: () => sizePresetOf(form.width, form.height) || 'custom',
  set: (value) => { /* parseSize → 同时 patch width + height */ },
});
```
选项 = `NAI_SIZES` 7 项 + `{value:'custom', label:'自定义（下面填宽高）'}`。
**声明式里它必须是独立的一个字段**（不是 width/height 的附属），靠
`options[].patch`（选项带多个键）+ `valueFrom`（当前值从两个键反推）表达。
**丢掉它 = 用户失去「选预设尺寸」这条路**，这是本阶段最容易丢的东西。

## 2. 块（`.cx-blk`）的标题 / 角标 / 说明 —— 一共 5 块，逐块核对

| 块 | 标题 | 块头右侧 | 字段 |
|---|---|---|---|
| 接口 | `接口` | 静态小字「连哪家 · 用哪个 Key」 | source(1) api_key(2) site(3) site_url(4) model(5) |
| 固定提示词 | `固定提示词` | **角标「N 字」= len(prompt)+len(prompt_end)+len(negative)** + 小字「每张图都带上」 | prompt(6) prompt_end(7) negative(8) quality(9) uc_preset(10) |
| 生成参数 | `生成参数` | 小字「模型给的 prompt 之外，画成什么样由这些定」 | sampler(11) schedule(12) steps(13) **尺寸(14+15)** seed(16) guidance(17) guidance_rescale(18) |
| 高级 | `高级` | 小字「先都按默认，画歪了再来动」 | smea(19) smea_dyn(20) decrisp(21) variety(22) straight_alpha(23) |
| 出图 | `出图` | 小字「成本上限」 | max_count(24) |

角标「N 字」是**动态**的 → 对应 `SettingsGroup.badgeOf`。

## 3. 动态文案 —— 必须用 `hintOf` / `group.hintOf`，不许降级成静态字

这 4 处以前是 computed，**内容是活的值**：

| 位置 | 旧表达 | 声明式 |
|---|---|---|
| 模型字段的小字 | `现在选的是 ${versionLabel}` → 「v4.5」或「不认识的模型名」 | `hintOf: v=>'现在选的是 ' + ((naiVersion(v.model)) || '不认识的模型名') + '。…'` |
| quality 字段的小字 | `开着会自动加上（各模型不一样）：${qualityWordsFor(form.model)}` | `hintOf: v=>'…：' + qualityWordsFor(v.model)` |
| 高级块的说明 | `v-if="!isV3"` 的那一段「SMEA / SMEA DYN / 减少伪影 是 v3 的字段…」 | `SettingsGroup.visibleIf: v=>naiVersion(v.model)!=='v3'` + `hint`（或 `hintOf` 拼出当前版本） |
| 固定提示词块角标 | `fixedChars` | `SettingsGroup.badgeOf` |

**静态小字**（原样搬，不要改写文案）：api_key 那段「NovelAI 官网 Account → Persistent Token…别把带 Key 的文件发给别人。」、
site 那段 CORS 说明、steps「1–50；28 左右够用，越高越慢越贵。」、seed「0 = 每次随机…」、
guidance「越大越贴提示词，太大会发硬。v3 默认 11，v4 起常用 5。」、
guidance_rescale「0–1，v4 起才认…」、max_count「模型一次调用最多能出几张（1–4）。生图按张收费，这是钱的上限。」、
smea_dyn「这两个是官方推荐的动态阈值组合…」、variety、straight_alpha「出 PNG 透明底…（只有 v5 的接口认这个字段）」、
uc_preset、model、尺寸「竖图立绘用 832×1216；宽高必须是 64 的整数倍。」、source 行「先只做这一家；OpenAI 兼容 / SD WebUI 之类以后加在这」。

## 4. 旧代码里那两个「按字段名特判」的硬编码 —— 本轮应当消失

1. `PluginDetail.vue:478` — `if (key !== 'guidance' && key !== 'guidance_rescale') value = Math.round(value)`
   → 声明式里由 `step`（0.5 / 0.02 < 1）决定，**不许再按字段名判断**。
   回归闸：`clampNumber` 对 `step:0.5` 的字段不取整，且**与字段 key 叫什么无关**。
2. `PluginDetail.vue:467` — `setBool` 里 `if (key === 'straight_alpha' && !straightAlphaOk.value) return`
   → 声明式里由 `visibleIf` 让控件**根本不出现**（比「点了没反应」更好）。语义等价，且不再有名字特判。

## 5. 我在旧代码里发现的**既有**不一致（本轮不许顺手「修」掉，只能原样保留或明确上报）

1. **`straight_alpha` 的版本口径有两套说法**：
   - `options.ts:107` 注释：「透明背景只有 v5 的请求会带」
   - `PluginDetail.vue:467` 注释：「透明背景只有 v4.5 / v5 认」
   - `options.ts:111` **代码**：`return version === 'v5'`（**只有 v5**）
   - 界面文案：「只有 v5 的接口认这个字段」
   → **代码与界面文案一致（v5）**，错的只是那句 v4.5 注释。改写时**以代码为准**，不要因为改了注释就顺手改行为。
2. **`guidance_rescale` 的可见性没跟版本挂钩**：它的小字写着「v4 起才认」，但旧界面在 v3 下**照样显示**（没有 `v-if`）。
   → 等价改写 = **不**加 `visibleIf`。擅自给它加条件是**行为变更**，不在本阶段范围内。
