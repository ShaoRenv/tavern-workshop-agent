## 3. 从 DSH 借来的东西（你问的）

**先说清楚**：我搜了整个仓库，**没有**一份专门的「DSH 优点」笔记文件 —— 上下文压缩时丢了。能确证的只有代码里留下的两处（`agent/guards.ts` 的「文案照 DSH」、`core/ports.ts` 的「单次调用预算跟 DSH 一个路子」）。下面这份是我按 DSH 的实际设计重组的，你确认或删改。

### 已经借到手的
| DSH 的做法 | 在我们这里的对应 |
|---|---|
| 工具卡压成一行、成组折叠 | 28px 工具卡、跑完才折叠 |
| 编辑前必须读过（观察策略） | observe-guard：没读过就改 → `NOT_OBSERVED` |
| 陈旧版本检测 | `entryVersion` FNV-1a 哈希 → `STALE` |
| 上下文修剪 + 预算 | prune-guard（8192/8193 阈值，只标记不删原文） |
| 同一工具反复调用要提醒 | repeat-guard（3/5/8 次） |
| 单次调用超时预算 | `ToolDef.timeoutMs` + `effectiveTimeoutMs` |
| 结构化输出校验 | zod schema，工具参数与预设都过 |
| 技能按需加载 | `skill()` 读正文，系统提示词只放名字+一句话 |
| 每一步都留痕可查 | `Session.events` 事件流（记录页时间线） |
| 静态检查必须绿才能交付 | tests 215 / tsc 0 / webpack exit 0 |

## 4. 拍过板的（不要重开）

1. 界面极简、长页面滚动、手机优先（点击区 ≥40px）
2. 工具卡 28px；连续调用跑完才折叠；失败/改动自动展开
3. 必须有 `● 运行中 · 第 N 轮`

5. 世界书范围定死在勾选的那些书，范围外一个字不出现

7. 存储放脚本变量；导入导出带上
8. 外部工具全权装载、不做门禁；信任交给人工审核；禁网只能靠隔离模式

10. 技能只有名字 + 一句话进系统提示词
11. 测试 / lint 保持绿
12. 相对 import 必须带 `.ts`
