## 2. 四个 bug（三个只有真浏览器能看见）

### B1 五个控件的显示值**不读已存的值**（严重）
`SettingsForm.vue` 里 `password / code / textarea / number / text` 五处都绑 `:value="draft[field.key] ?? ''"` ——
**只看本地草稿，完全不看 `values`**。于是已存的值在界面上一片空白：
真机上 `steps`（存着 28）、`seed`、`guidance`、`max_count`、`api_key`、三段固定提示词**全是空的**。
用户会以为自己填的 API Key 丢了，还可能把空的存回去。

**讽刺的地方**：`commit()` 里读的是对的（`field.key in draft ? draft[field.key] : model.value[field.key]`）——
**只有「显示」这一半错了**，所以是「能存不能看」，最难被自测发现。

修：新增纯函数 `inputValue(field, draft, values)`（草稿优先，否则读 values，都没有给 `''`，数字转字符串），五处统一走它。

### B2 原生 `<select>` 的 change 处理器收到 **Event 却被当 string**（严重）
`@change="onSelect(field, $event)"` → `onSelect(field, value: string)` 拿到的是 DOM `Event` →
`asText(event)` 得 `''` → `buildPatch` 写出 `{[key]: ''}`。
**受害字段 = 所有非 SegBar 的下拉**：`model` / `uc_preset` / `sampler` / `schedule`。
真机现象：切「模型」后小字立刻变成「现在选的是 **不认识的模型名**」。
SegBar 那条路没事（`@update:model-value` 给的就是字符串）—— **一种写法坏、另一种好**，只有真机点下拉才试得出来。

修：新增纯函数 `selectValueFrom(payload)`（字符串直通 / 类事件取 `target.value` / 其余给 `''`），`onSelect` 内部归一。

### B3 [阻塞] 扩展形态下数据**每刷新一次就丢一次**（两层原因，都要修）
**第一层：作用域。** 数据存在酒馆助手的**脚本作用域**里，而扩展**没有脚本** ——
实测 `TavernHelper.getVariables({type:'script'})` 直接抛 `获取变量失败, 未指定 script_id`
（`getScriptId` 在真酒馆里根本不存在、`__CX_SCRIPT_ID__` 为 null）。
读失败 → store 用默认值启动 → 紧接着的 save **把默认值写回去** → 覆盖用户数据。
修：按形态分流 —— 脚本形态保留 `{type:'script', script_id}`（老数据原地不动），扩展形态用 `{type:'global'}`；读写共用**同一个**缓存的作用域。

**第二层（更隐蔽）：原生适配器「已知键清单」冷启动为空。**
ST 原生变量接口**按 key 读得了、但列不出全部**（实测：`Object.keys(ctx.variables.global)` 只有
`["get","set","del","add","inc","dec","has"]`，`{...g}` 与 `JSON.stringify(g)` 都是 `{}`，
而 `g.get('cx_assistant_v1')` 返回完整数据）。
所以原生「读整表」= 按一张**已知键清单**逐个 get —— 而那张清单原本**只记本进程写过的键**：
冷启动（刚刷新）时它是空的 → `getVariables` 返回 `{}` → 上层以为没数据 → 默认值 → 写回。
修：**由应用声明要读的键**（`declareNativeKey`，在 `readStoredRootData()` 开头声明，不依赖 import 顺序）。

**让事故变成静默的最后一环**：读接口返回 `{}` **不抛错** → 读结果记成 `'empty'`（读通但没这个 key）
而不是 `'failed'`，而写保护只拦 `'failed'`。**「接口不支持枚举」≠「存储里没有数据」** ——
修：适配器提供 `_canEnumerateVariables()`，不能枚举且没读到 key → 记 `'failed'`，拦住写入。

### B4 修完 P4-10 后留下的两块重复代码（我复核时抓到）
`core/native.ts` 里数据作用域那一整块**存在两份**（一条只删了一半），
`isExtensionRuntime / dataScope / describeDataScope / DataScope` 全部重复声明，tsc 报 TS2300/TS2323/TS2393。

以及 `'unavailable'` 语义**没接上 storage**。三件事都是「实现写好了、最后一米没接」。

## 3. 为什么单元测试和 SSR 全都没抓到（一条给下轮的教训）

| 盲区 | 具体表现 |
|---|---|
| **「控件存在」≠「控件里有值」** | SSR 断言遍历了字段、断言了控件分支与文案，但**从没给定一个非空的已存值再断言它出现在 HTML 里**——空 `<input>` 也是 `<input>`。 |
| **SSR 不触发 DOM 事件** | `renderToString` 里 `@change` 处理器**一行都不会执行**，所以「把 Event 当字符串」这条路径在 SSR 里是**死代码**，怎么渲染都发现不了。 |
| **纯函数测不到「组件真的接上了」** | `inputValue` / `selectValueFrom` 单测全绿，但「`.vue` 里到底调没调、参数顺序对不对」它管不着；源码级闸只能查「有没有用」，查不出「用得对不对」。 |
| **门禁绿 ≠ 功能对** | 本轮 507 条测试、tsc、eslint、build 全绿的同时，界面上 API Key 是空的、下拉选不中、刷新就丢数据。 |

**可复用的做法（本轮补上的）**：给显示值断言**必须给具体值 + 断言具体输出**，并且带一条「反例自检」
（用旧写法渲染一遍、断言那个值**不出现**）——否则断言可能恒真。

## 4. 两个测真机时的陷阱（我踩过，写下来免得下一个人重踩）

1. **后台标签页的定时器会被 Chrome 节流。** `store.save()` 有 2500ms 防抖；酒馆页不在前台时，
   这个防抖可能**几十秒都不触发**。我因此把「没落盘」误判成 bug（实际是我刷新得太早）。
   测落盘前先 `select_page` 把目标页切到前台。
2. **`<select>` 的显示值会骗人。** 存储值不在选项里时，浏览器**回落到第一个选项** ——
   看起来完全正常。判定要看**旁边的小字**或者**落盘原文**，不能只看下拉框显示了什么。

## 4.5 我自己也被「假绿」骗过一次（写下来，因为它是本次最值得记住的一条）

推送前我跑门禁得到 **507/507 全绿**，而**独立验收跑同一个命令得到 506/507、1 fail**。
差别的根源不是谁跑错了，而是：**`bundle_artifact.test.ts` 断言的是一条写死的旧文案**
（`'没有可用的酒馆助手脚本变量接口'`，扩展化后已改成形态无关的「没有可用的变量写入接口」），
而我那次跑测试用的是**上一次 `pnpm build` 留下的旧产物** —— 旧产物里恰好还有那句旧文案，于是**测试通过**。

**教训有两条，都跟「测试」这个工具本身有关：**

1. **「产物级断言」必须跟着产物走。** 断言里写死一句产品文案，产品改了文案、断言就过期；
   而过期表现为**红**（这次是独立验收抓到的）或**假绿**（产物还没重建时）。
   现在这条改成**从 `core/storage.ts` 现取文案**再断言产物里有它 ——
   顺带成了「**有没有重新 build**」的闸：改了源码忘构建，它就会红。
2. **门禁绿 ≠ 该信。** 我自己的 §5 报告写「507/507」，独立验收一跑就不同 ——
   这正是为什么本轮坚持要有**独立验收**，而不是让写代码的人自己报绿。

**所以：`node --test` 之前必须先 `pnpm build`**，否则 `bundle_artifact` 那一组测的是旧产物，会给出没有意义的结论。

### 4.6 修好之后，新守卫**只长了一半的牙**（独立验收实测，已知限制）

独立验收对新的「从源码现取文案」守卫做了四个实验，结论是**部分有效**：

| 改动（都不重新 build） | 期望 | 实测 |
|---|---|---|
| 文案**括号后**加一个字符 | 红 | **绿** ❌ |
| 两处的 `接口` → `通道`（落在捕获段内） | 红 | **红** ✅ |
| 只改**其中一处**（该文案在 storage.ts 有 :821 / :844 两处） | 红 | **绿** ❌ |
| 还原后重跑 | 绿 | **绿** ✅ |

原因：正则 `没有可用的[^'"，（）\n]*接口` 的字符类**排除了 `（`**，所以只捕获到「没有可用的变量写入接口」；
且 `.exec()` **只取第一处**，两处文案改了一处就看不见。

**它抓得住最常见的情形**（文案措辞改动、两处一起改 → 红），所以**没有拦着推送**；
但「只改一处」和「改括号后」这两个口子是真的 —— 记在这里，不要以为它是全牙的。
收紧方向（未做，记在 task-27）：两处一起取，或断言产物里 `'保存失败：'` 的出现次数与源码一致。
