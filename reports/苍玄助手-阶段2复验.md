## ① 通过项

### A. F-A（严重项）—— **运行时那层真的不给** ✅
**代码（读）**
- `run/runner.ts:217-220` `liveToolDefs(defs, state)`：用 `pluginAllTools(state)` 当白名单 —— 底座工具（`toolOwner === 'base'`）永远留，插件工具只在「插件开着」时留。用 `pluginAllTools`（注册的全部）而不是 `pluginTools`：按需工具 `entry_meta` 的 **def 要在**，能不能发由 `resolveCaps` 按 `default_on` 定。
- `run/runner.ts:582` `const toolDefs = resolveToolDefs(liveToolDefs(registry.defs, args.data), overrides)` → `:586` caps → `:706 tools: toolDefs` / `:689 enabled_tools: caps.tools`；`agent/loop.ts:167-170 toToolSpecs(tools, enabled)` 只做**交集** → 被筛掉的 def 不可能出现在请求体里。
- 也就是说三层门禁齐了：界面清单（pluginAllTools）/ 显示用 globalCaps（pluginTools）/ **运行时 toolDefs（liveToolDefs）**。

**我的运行时探针（6 例，全部 PASS；直接驱动真 runner，假 fetch 抓 `body.tools`）**
```
世界书关着（预设跟随全局）                实发(3) = skill, read_skill_file, submit     ← 不含任何 wb_/entry_
世界书开着（预设跟随全局）                实发(9) = 6×wb_* + skill, read_skill_file, submit（无 entry_meta）
世界书+生图都关 + 预设显式勾 gen_image/wb_list  实发(0) = （def 被筛掉 → 交集为空）
都开着 + 预设显式勾 gen_image/wb_list     实发 = wb_list, gen_image（门禁不过度拦截）
只关世界书（生图默认关）                  实发(3) = skill, read_skill_file, submit
```
（第 5 例我第一次写成顺序敏感断言报了 FAIL，实际两个名字都在，是我的断言问题，不是代码问题 —— 记下来免得误读探针输出。）

**测试**：`✔ F-A 回归闸：运行时也认插件开关（关掉的插件，工具连 def 都不进这一轮）`（`tests/苍玄助手/plugin_registry.test.ts:192-218`）实跑通过：世界书关 → `wb_list` 与 `entry_meta` 一起从 def 里消失；开生图 → `gen_image` 才进来。

### C. H3 —— goto 落点 ✅（immediate / 重复点 / 旧意图不劫持）
**机制（读）**：`App.vue:223-240` `segIntent` + `segSeq`：`goto('capability')` → `requestGotoSeg({page:'settings', seg:'capability', sub:'tools'})`，**先记意图再 `store.setTab`**；`SettingsView.vue:519-527` watch **immediate** 落一级段、靠 `SettingsView.vue:321-328` **模块级** `appliedIntentAt` 认「这条已消费」（跨挂载保留）；`CapabilityView.vue:172-178` watch 认**对象身份**落二级段。
