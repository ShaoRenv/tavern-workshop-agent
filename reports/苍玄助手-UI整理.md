# 苍玄助手 · UI 整理（问题清单 + 归位方案）

> 触发：用户指出「技能与工具有多处，前端乱了」。实测确认，问题真实存在。
> 责任在 Lead：team 每加一个功能都就近塞进设置页，没人管信息架构。

## 一、病根：同一件东西的三个身份没分开

| 身份 | 例子 | 该在哪 |
|---|---|---|
| **库** | 工具本身、技能本身、预设本身 | 各自的页面 |
| **本次配置** | 这个预设用哪些工具 / 技能 | 预设编辑里（只勾选） |
| **全局设置** | 接口、数据备份 | 设置页 |

现在全挤在设置页，所以同一份 13 行工具清单在一页里出现两次。

## 二、实测（这篇是刚在真酒馆里点开、截图、逐页抄下来的）

| 页 | 实际内容 |
|---|---|
| 立绘 | 提示词（用哪个预设）→ 角色 → 用户需求 |
| 世界书 | 范围（勾哪些世界书）→ 条目勾选 |
| 对话 | Agent｜聊天 分段 → 草稿条 → 消息 → 状态行 |
| 技能 | 技能库 + 编辑弹窗 + 参考文件弹窗 |
| 记录 | 会话列表 → 时间线 |
| 设置 | **接口 → 工具（13 行）→ 数据 → 预设（系统提示词 + 工具 10/13 又 13 行 + 技能 2/2）** |

### 重复项（用户说的就是这个）
1. **工具 ×2，而且在同一页**：设置·工具（可编辑 13 行）＋ 设置·预设·工具（勾选，同样 13 行同描述）
2. **技能 ×2**：技能页（库）＋ 设置·预设·技能（勾选 + 「去技能页管理 →」，等于自己承认该在别处）
3. **预设 ×2 字样**：设置·预设（编辑）＋ 立绘页顶部（选择）—— 这条本身合理，但字面重名让人以为重复
4. **设置页四大块、约 9 屏**：接口 / 工具 / 数据 / 预设，手机上翻不完
5. **流程被切开**：立绘页有「去设置 →」，说明要做立绘得先跳到设置配接口

## 三、目标信息架构

原则：**库 / 本次 / 全局 分开；一个东西只有一个入口。**

| 页 | 只放这些 |
|---|---|
| 对话 | Agent｜聊天、草稿条、消息、运行状态 |
| 立绘 | 选预设、角色、用户需求、产物 |
| 世界书 | 范围（勾哪些世界书）、条目勾选 |
| **能力**（原「技能」页扩容） | 分段：**工具｜技能**。工具：提示词 / 参数 / 超时 / 停用；技能：库、编辑、参考文件 |
| 记录 | 会话列表 + 时间线 |
| 设置 | 分段：**接口｜预设｜数据**。预设里工具/技能改成**紧凑多选（弹窗）**，不再复制整份清单；顶部一句「改提示词去 能力 页 →」 |

页签仍是 6 个：对话 / 立绘 / 世界书 / 能力 / 记录 / 设置（只把「技能」扩成「能力」）。

## 四、改动清单（代码级，只碰 UI 层）

1. `core/types.ts`：`TAB_IDS` 的 `skills` → `capability`，含老数据 `active_tab` 迁移（`skills` 自动落到 `capability`）
2. `components/ui_types.ts`：`TAB_LABELS` 同步
3. `App.vue`：路由与事件转发跟着换
4. 新增 `views/CapabilityView.vue`：SegBar（工具｜技能），吃下原设置页的工具区 + `ToolDetail` + `ToolPromptSheet` + `SkillsView`
5. `views/SettingsView.vue`：删工具区、删技能区；预设的勾选换紧凑多选弹窗（预计 599 行 → 350 行左右）
6. `global.css`：能力页样式
7. 验收：**375px 手机宽度下，每页无横向滚动、无重复清单**；`tests` 保持 215 绿、`tsc` 0 错

## 五、不动的东西（维持已拍板）

工具卡 28px、连续调用跑完才折叠、长页面滚动、手机优先、点击区 ≥40px、**不嵌套小滚动区**（二级导航用 SegBar 切内容，不是内嵌滚动容器）、工具提示词必须能在界面改。

## 六、为什么现在值得做

外部工具导入（P2）会让工具列表继续变长，生图工具也要进来。**现在不抽干净，D 批做完会更乱。**
