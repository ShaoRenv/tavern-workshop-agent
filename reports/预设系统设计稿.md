## 1. 核心机制：默认预设只读 + 派生

### 1.1 现状的错

`presets/builtin.ts:445-462`：

```ts
// 规则：只补不覆盖。同 id 已存在就原样保留（用户可能改过内置内容，
// 刷新时不能把用户的编辑冲掉）；只有缺失的 id 才插入。
for (const preset of createBuiltinPresets()) {
  if (!presetIds.has(preset.id)) presets.push(preset);
}
```

**这个设计的问题**：

| 用户行为 | 现在的结果 | 应该的结果 |
|---|---|---|
| 直接改默认预设 | 改动留下，**默认预设再也不会更新** | ❌ 不该允许直接改 |
| 想基于默认预设改 | 只能直接改默认的 | ✅ 应该「另存为」一份再改 |
| 插件升级带了新默认预设 | **看不到**（被用户的旧版挡住） | ✅ 默认预设应该跟着升级 |

### 1.2 新机制

```
默认预设（builtin: true，id 形如 builtin-*）
   ├─ UI 显示「内置」标记
   ├─ 不可编辑、不可删除（删除已保护）
   ├─ applyBuiltins() 每次载入**强制写回最新版**
   └─ 用户点「另存为」→ 派生
        ↓
     用户预设（builtin: false，id = uid()）
       ├─ 完全可编辑、可删除
       ├─ 不受内置更新影响
       └─ 可导出、可分享
```

### 1.3 改动点

```ts
// presets/builtin.ts 的 applyBuiltins()
export function applyBuiltins(data: RootData): RootData {
  const presets = [...data.presets];
  for (const preset of createBuiltinPresets()) {
    const i = presets.findIndex(p => p.id === preset.id);
    if (i < 0) presets.push(preset);          // 没有 → 插入
    else presets[i] = preset;                  // 有 → **强制覆盖成最新版**
  }
  // 用户预设（builtin: false）原样保留，不动
  ...
}
```

**关键**：只覆盖 `builtin: true` 的，用户预设**一个字都不碰**。

### 1.4 「另存为」怎么做

```ts
function duplicatePreset(id: string): Preset {
  const src = data.value.presets.find(p => p.id === id);
  const copy: Preset = PresetSchema.parse({
    ...src,
    id: uid('preset'),        // 新 id
    name: src.name + ' 副本',
    builtin: false,          // 关键：派生出来的是用户的
  });
  data.value.presets.push(copy);
  data.value.active_preset_id = copy.id;
  return copy;
}
```

**⚠️ 核实结果：这个已经做对了**（`App.vue:752-756`）：

```ts
if (action === 'duplicate') {
  const copy: Partial<Preset> = { ...target, name: target.name + ' 副本', builtin: false };
  delete copy.id;                    // 让 addPreset 生成新 id
  store.addPreset(copy);
}
```

**所以「派生」不用做，只要把「内置只读」补上就行** —— 现在的缺口是：用户可以直接编辑默认预设，而默认预设又「只补不覆盖」，导致内置永远更新不了。

## 2. 工具提示词：跟预设走（用户定案）

### 2.1 定案

**工具提示词覆盖存进 `Preset`，跟预设一起切换。**

```
预设 A
  ├── items（系统提示词 / 上下文层）
  ├── tools（勾了哪些工具）
  ├── skills（勾了哪些技能）
  ├── use_global_caps
  └── tool_overrides   ← ★ 新增：工具提示词覆盖，跟预设绑定
```

**切换预设 → 工具提示词自动跟着换。** 不用单独管理、不用单独切换。

### 2.2 那 `RootData.tool_overrides` 还留着吗？—— 留，当临时区

| 层 | 作用 | 谁写 |
|---|---|---|
| `RootData.tool_overrides` | **当前生效的那份**（临时区） | 用户在工具页改 → 立即生效 |
| `Preset.tool_overrides` | **预设里存的那份** | 用户点「存进预设」/ 切预设时写入 |

**为什么保留临时区**：用户可能「临时改一句试试效果，不想存」—— 那就改 `RootData.tool_overrides`，不碰预设。

### 2.3 三个动作

| 动作 | 做什么 |
|---|---|
| **用户改工具提示词** | 写 `RootData.tool_overrides`（现有路径，不动） |
| **切换预设** | 把新预设的 `tool_overrides` **整体写进** `RootData.tool_overrides` |
| **存进当前预设** | 把 `RootData.tool_overrides` **存回** `Preset.tool_overrides` |

### 2.4 边界情况

| 情况 | 处理 |
|---|---|
| 预设没有 `tool_overrides` 字段（老数据） | 视为空对象 `{}` → 切过去等于「全部跟随内置默认」 |
| 用户改了临时区但没存，然后切预设 | ✅ **已定：提示一次**「当前改动还没存进预设，切走会丢」→ 用户选「存 / 丢弃 / 取消」 |
| 默认预设 | 只读，所以它的 `tool_overrides` 不可改；用户要改就另存为 |

### 2.5 改动点

```ts
// core/types.ts · PresetCoreSchema 加一个字段
tool_overrides: ToolOverrideMapSchema.default({}),
```

**不用新增任何顶层块**，`RootData.tool_overrides` 保持不动。

## 3. 导出/导入分三类（D8）

### 3.1 现状

`SettingsView.vue:196-198` 只有三个按钮：
- 导出全部数据
- 导出（不含 API Key）
- 导入数据

**是整棵树，不分三类。**

### 3.2 新设计

| 类 | 导出什么 | 文件格式 |
|---|---|---|
| **① 工具提示词** | `tool_overrides` 或某个 `tool_prompt_preset` | `{ kind: 'tool-prompts', version, overrides }` |
| **② 预设** | 某个 `Preset`（含 items / tools / skills / use_global_caps） | `{ kind: 'preset', version, preset }` |
| **③ 技能** | 某个 `Skill`（含 files[]） | `{ kind: 'skill', version, skill }` |

**为什么加 `kind`**：导入时能校验「你导的是技能，别往预设里塞」。

### 3.3 导入的处理

| 情况 | 处理 |
|---|---|
| 同 id 已存在 | 提示用户：「已有同名，覆盖 / 另存为新的一份？」 |
| 撞内置 id | **拒绝**，提示「这是内置的，不能覆盖；可以另存为新的」 |
| 格式不对 | 明确报「这个文件是 X 类，导入不到 Y」 |
