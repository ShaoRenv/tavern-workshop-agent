## 3. 本轮的关键判断（下一轮别推翻）

### 3.1 「删 resolveScriptId/scriptScope/VariableScope」——**保留未删**
我原来的任务描述写了要删。host-bridge 报上来：`tests/苍玄助手/core_script_scope.test.ts`（291 行）

### 3.2 `deps.generateRawImpl` 的裁决（选项 A）
15 处测试用它当唯一注入手段，真删必红 11 个用例。判据：
- `globalFunction()` = 第二条**宿主解析链** → 必删
- `deps.generateRawImpl` 的 `impl ?? globalFunction(...)` = 把「注入」和「全局解析」缝一起 → 也是第二条链 → 必删
- `deps.fetchImpl` = **调用方指定的接口地址**（用户填了自己的 API 才走），语义不同 → **保留**

执行：3 个测试文件把 `createTransport({generateRawImpl})` 换成 `setHostBridge({generateRaw})`，
**断言与用例名一个字未动**。这是「测试跟着单一契约走」，不是放宽断言。

### 3.3 影子表整体退役（native-adapter 发现的，比我报的更严重）
我报的是多标签页场景；他补了第二处：`readVar` 原生读不到时**回落到内存缓存**，
拿可能过期的值冒充真值。已全退役：
- 读只问原生，读不到就**缺席**
- 写只写原生，写不进去**明确警告**（绝不假装成功）
- 整表读改为「已知键清单 + 逐个原生读」

判据：**宁可明确失败，不要静默给出一个可能是错的值。**

### 3.4 存储能力拆两条（不要合成一条）
- `vars.keyed`（按 key 读写）→ ST 原生始终可用
- `vars.table`（整表读写）→ **只有酒馆助手给得了**，纯原生环境明确 unavailable

### 3.5 宏的三层静默失败（⚠️ 本轮最重要的发现，下一轮别推翻）

ST 宏系统的**所有失败都是静默的**。本轮在真机上把三层全挖出来了，缺一层都查不出问题。

**第一层：参数名错 → 注册「成功」但永不替换**
- 真名是 **`unnamedArgs`**；`minArgs`/`maxArgs`/`unnamedArgDefs` 都是错的（`minArgs` 是**产物**字段）
- 默认 `strictArgs=true` ⇒ 参数个数不符不替换
- **不变量：注册后必须自检一次**（`native.ts` 的 `registerTavernMacro` 有四道闸 + 失败注销回滚）

**第二层：宏名非 ASCII → 压根不会被词法器识别**（本轮新发现）
- ST 规则：`/^[a-zA-Z][\w-]*$/`（`MacroLexer.js:17`、`MacroRegistry.js:487`）
- **中文宏名永远不生效**，实测对照（同机同 registry）：

  | 注册名 | 结果 |
  |---|---|
  | `cxAscii_OK` | ✅ 正常替换 |
  | `cx_dash-bad` | ✅ 正常替换（连字符合法）|
  | `cx中文名` | ❌ 保持字面量 |
  | `cxMixed混合1` | ❌ 保持字面量 |

  `registry.hasMacro('cx中文名') === false` —— 但 `register()` **不抛错**。
- **对策**：`PluginMacro` 新增 `tavernAlias`（ASCII 词根）。面板内继续用中文名
  （走我们自己的渲染器，不经酒馆词法器）；角色卡里用 `{{cx_image_prompt}}`

**第三层：老 API 与新 API 签名不兼容**（本轮新发现）
- 老（JSR）：`registerMacroLike(regex: RegExp, replacer: () => string)`
- 新（ST）：`macros.register(name: string, { handler, unnamedArgs })`
- 把新 API 直接当老 API 用 → **不抛错、也不生效**。适配层补了签名翻译
  （`macroNameFromLegacyRegex` 从正则里反解宏名）

**这三层叠在一起，就是那条历史悬案「`registerMacroLike` 端到端从没验证过」的真因。**

**通用判据（本轮反复用到的）**：
> **宁可明确失败，也不要静默给出一个看起来对的结果。**

本轮所有修复都遵循它：宏名不合法 → 明确拒绝并报原因；
写入失败 → 明确警告（不假装成功）；读不到 → 返回缺席（不拿缓存冒充真值）。

## 4. 我修的那个真 bug（本轮最有价值的发现）

**扩展的 CSS 被拆进异步 chunk，导致界面裸样式。**

`manifest.json` 的 `css` 字段**只能指向一个样式表**，酒馆只加载它。
但我们用 `await import()` 动态加载界面 → 顺带拆出异步 CSS chunk `965.index.css`（22KB，**设计系统全在里面**），
而 `index.css` 只有 71 字节 → **悬浮球和面板全裸，且控制台一声不响**（没 404，因为压根没人请求它）。

修法（`webpack.config.ts`）：extension 入口下加
`splitChunks.cacheGroups.styles = { type: 'css/mini-extract', chunks: 'all', enforce: true }`，
把所有样式合成一个 chunk 落到 `index.css`。JS 仍照常异步分包（收益保留）。

**教训：`manifest.css` 是唯一入口，任何 CSS 分包都是静默失效。**

## 4.1 另外两个只有真机/构建才暴露的缺陷（本轮一并修了）

**（a）悬浮层被挂在设置抽屉里 → 几何被压成 0×0**

一开始照官方模板把容器 append 到 `#extensions_settings2`。真机实测悬浮球
`getBoundingClientRect() = {0,0,0,0}`、`offsetParent = null`。祖先链：

    #extensions_settings2 → #extensions_block → #rm_extensions_block.drawer-content.closedDrawer  (display:none)

**抽屉关着时 ST 给它 `display:none`**，整棵子树的几何被压成 0。
后果：**用户不打开设置抽屉就永远看不见悬浮球，且不报任何错**。

我们的形态是「常驻悬浮球 + 浮层」，生命周期与设置抽屉无关 —— 所以改挂到 `document.body`。
（`src/extension/index.ts` 的 `mountTarget()` 现在返回 body；`extension_contract.test.ts` 有闸守着。）

**（b）旧 chunk 越积越多 → 发布非原子**

chunk 是 contenthash 命名的，每改一次代码就多一个新名字。
webpack 的 `output.clean` 只清**本次 compilation 记过账**的文件 —— 实测一轮开发堆了 **9 个**，
而 `index.js` 只引用其中 1 个。

危害：玩家「覆盖拷贝」更新时新旧混在一起，一旦 index.js 与 chunk 版本错配就是**白屏**；
顺带包体虚胖（8 个没人引用的 228KB 文件）。

修法：`webpack.config.ts` 新增 `prune_stale_chunks()`，构建收尾按 index.js 的引用清掉没用的 chunk
（实测清掉 16 个）。`extension_contract.test.ts` 有闸守着。

**（c）另一个小坑：`SlotTarget` 空壳组件转发 slot 会渲染成空**

`<div class="cx-pw"><SlotTarget /></div>` 里，子组件 setup 拿到的 slots 是**它自己**的，
而没人给它传过 slot → 渲染成空。真机现象：点开悬浮球后 `.cx-pw.childElementCount === 0`
（面板是个空盒子、球照常显示），**控制台一声不响**。
改成模板里直接写 `<slot/>`（在本组件渲染作用域里求值，才是父组件传进来的那份）。
