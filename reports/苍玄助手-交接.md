## 2. 这一轮做了什么（2026-09）

### 2.1 真酒馆首次接入 —— 抓到一个真 bug 并修掉
把开发版脚本装进酒馆全局脚本库（装之前已备份 `settings.json` 到 `backups/`），面板能起、按钮能点，但控制台报：

```
[苍玄助手] 以下酒馆助手接口不可用：replaceVariables、updateVariablesWith、getScriptId、
getGlobalWorldbookNames、getCharWorldbookNames、getChatWorldbookName、replaceWorldbook、
createWorldbook、deleteWorldbook、getModelList、substitudeMacros
```

**根因**：`tavern_script/panel.js` 的桥接表是手写死名单，只桥了 **8 个**，而应用要 **19 个**（名单在 `tavern_script/frame.html` 的 `HOST_KEYS`）。
后果是**读得到世界书、写不了世界书**，而且 `getScriptId` 拿不到 → 脚本变量作用域丢了 → 存储也会坏。

**修法**：`panel.js` 改成按 `HOST_API_NAMES` 数组逐个桥接，先取脚本上下文的全局函数、再退回 `TavernHelper[name]`。
（`getScriptId` 只在脚本 iframe 的 window 上，不在 TavernHelper 对象上，所以必须先取全局。）
实测：**19/19 全桥上，缺失 0，`__CX_SCRIPT_ID__` = 本脚本 id**。

> 教训：`frame.html` 的 `HOST_KEYS` 和 `panel.js` 的桥接名单**必须同步**。以后加接口两边一起加。

### 2.2 局域网 / 手机调试（用户提的需求）
手机上访问酒馆面板时，两个原因导致拿不到脚本：
1. 开发服务器原来只绑 `127.0.0.1` → 局域网里任何设备都连不上。现在绑 **`0.0.0.0`**。
2. 实时监听器地址是 `http://localhost:6621` → 手机上的 localhost 是手机自己。现在改成局域网地址。

另外 `frame.html` 里的 `app.js` / `app.css` 原来写死 `http://127.0.0.1:8787`，手机加载会失败 → `dev_server.mjs` 改为**按请求的 Host 头拼绝对地址**，本机和手机各取各的。

开发版脚本正文（`tavern_script/dev_loader.js`）改成**候选地址依次尝试**：`http://<局域网IP>:8787` → `http://127.0.0.1:8787`，任一成功即停。

**本机局域网 IP = `192.168.71.15`**（用户曾误填 `.51`）。IP 变了要重新 `pnpm dev:json` 生成脚本 JSON 并重导（`<局域网IP>` 是生成时写进去的）。

### 2.4 预设合并 + 特殊层（口径见 `reports/苍玄助手-预设与上下文.md`）

- **`Preset` 不再有 `kind` / `system` / `messages`**，只有 `items[]`：
  `{type:'message', role, content}` 或 `{type:'special', id, name, kind:'context'|'user', enabled}`
- **`{{上下文}}` 宏弃用**：上下文只以**特殊层**存在，运行时**原生展开**（复用 `agent/loop.ts` 的 `turnsToMessages`），不再有 `【用户】` 文本转写。`formatHistory()` 保留只为兼容老预设。
- **`{{用户需求}}` 宏保留**（内置预设还在用）；另有 `special:user` 特殊层，展开成真正的 `role:'user'` 消息。
- **两级能力启用**：`use_global_caps`
  - `false`（默认）= 跟随「能力」页全局（工具走 `ToolDef.default_on`、技能走 `skill.enabled`）
  - `true` = 只用预设自己的 `tools` / `skills`
- **是不是 agent 由「解析后的工具集」决定**：`isAgentPreset(preset, globalCaps)` = `resolveCaps(...).tools.length > 0`。真实函数都在 `core/types.ts`（`resolveCaps` / `isAgentPreset` / `GlobalCaps`）。
  - ⚠️ 迁移口径：老 `kind:'plain'` → `use_global_caps: true` + `tools: []`（立绘这类必须**继续走普通 LLM 路径**）；老 `kind:'agent'` → `false`。别搞反，搞反了立绘会跑去调工具。
- `DATA_VERSION` **3 → 4**，迁移在 schema 层 `z.preprocess(migratePresetItems, …)`（所有读入口都过）+ storage 版本段兜一遍；item id 用 `<presetId>-system` / `-item-N` **确定性**生成，所以幂等。
- 对话页 ⚙ → 「对话设置」Sheet：切聊天 / 切预设 / 删除当前对话（复用 store 现有数据层）。
- 能力页工具详情里的「在当前这个预设里启用」开关：**跟随全局时不显示**（点不动就是死控件），改成说明文案。

### 2.5 保存链路（手机卡顿的根因，已改）

**实测根因**：酒馆每次保存设置，客户端要 **POST 46.7 MB** 到服务器（`/api/settings/save` 的 `content-length = 46670868`，整份 settings 全量回传；`extensionSettings` 25.7 MB，其中酒馆助手脚本库 9.7 MB —— 大头是用户自己的「小说转聊天记录」6.5 MB）。我们自己只占 7 KB。

所以优化方向是**减少次数**，不是减少体积（分片存储对这个问题没用 —— 上传的是整份 settings）。

- **删掉** `App.vue` 的 `watch(store.data, …, {deep:true})`：它让任何变更都深度遍历整份数据并调度保存。
- 改成**显式写点**：store 动作内部 `save()`；各 view 的直接变异（世界书勾选 / 立绘角色 / 接口字段 / 预设本体 / 技能开关 / 会话模式）统一 `touch()` → `emit('change')` → `App.vue` 的 `@change="store.save()"`。**新增写点时必须接线，否则就是静默丢数据。**
- `stores/app.ts` 新增 `holdSaves()` / `releaseSaves()`（计数嵌套）/ `flushSaves()` / `withHeldSaves()`；**agent 运行期 hold，finally release，整段只写一次**；挂起期间 `save(true)` 仍立即写。
- 防抖 **400ms → 2500ms**（`SAVE_DEBOUNCE_MS`）；`visibilitychange` 隐藏时 `flushSaves()` 兜底。
- ⚠️ **残留风险**：`run/runner.ts` 有三处绕过 store 直接改 data（`attachSkill` 推技能、`syncDrafts` 写草稿、`liveSession().round++`）。它们现在靠 `App.vue` 的 runOnce（hold + finally + 收尾 save）覆盖；**如果以后不经 runOnce 直接调 `runner.runAgent`，这三处不会落盘**。建议后续改成回调。

## 8. 用户口径（别猜，这些是拍过板的）

- 界面**极简、长页面滚动**，不要内嵌小滚动区，不要拥挤
- **手机优先**：点击区 ≥40px、label 在控件上方；375px 宽不许横向滚动
- 工具调用卡**一行 28px**；连续调用**跑完之后**才折叠成 `▸ N 次工具调用`；失败/改动自动展开；生图卡永远展开
- 要有**固定可见的运行状态**（`● 运行中 · 第 N 轮`）—— 用户最烦「看不到 LLM 在干什么」
- 工具提示词必须能**在界面上改**，而且要有固定入口（列表行 ✎）
- **世界书范围定死在用户勾选的那些书**，范围外的名字一个字都不出现
- **写操作只落草稿**，落地必须用户点保存；存储放脚本变量；导入导出要带上
- **别乱动酒馆环境**：改之前备份，只动必要项（这一轮只改了脚本库 + 监听器地址）
- **外部工具全权装载、不做门禁**；禁网只能靠隔离模式
- 用官方链路做自动推送（`pnpm dev:port` + 酒馆助手「实时监听」），**不做自动重载动画**
- 技能只有名字 + 一句话进系统提示词；`create_skill` 默认关
- `gen_image` 保留但默认关（用户以后要接生图，走外部工具形态）
- 测试 / lint 保持绿；**UI 验收由用户自己做**
- 相对 import **必须带 `.ts` 后缀**（`node --test` 直接跑 TS）
- 技术选型：**脚本 → 扩展的重构押后**，先跑通再说

## 9. 环境备忘

- DSH 会话文件策略 danger-full-access，**审批提示全关**：不要设置 `sandbox_permissions`
- `C:\Program Files\DSH Desktop\resources\app` 是 DSH 自己的 checkout，只能用来查 DSH，别当工作目录
- 酒馆**完全没有 CSP**（`src/server-main.js:104` helmet `contentSecurityPolicy: false`）→ 远程 `import()`、blob worker 都不受限
- 脚本 iframe 创建方式：`JS-Slash-Runner/src/panel/script/iframe.ts`（srcdoc + `<script type="module">`，无 sandbox 属性）
- 8788 端口被占用（Edge 连着某个服务），所以开发服务器用 **8787**
- **`package.json` 是 webpack 的命脉**：逗号写错会让 `npx webpack` 直接失败（tsc / node --test 不看它，很容易漏）—— 改完 scripts 一定 `node -e "require('./package.json')"` 验一下
- Windows 防火墙**三个 profile 全关**，所以局域网调试不用加规则；非管理员也能改
