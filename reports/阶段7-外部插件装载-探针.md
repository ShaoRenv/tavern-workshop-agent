## 1. ✅ 已验证：**能不能加载外部 JS** —— 三条路全通

**结论**：三条路**都可行**，在真酒馆（http://127.0.0.1:8000）页面上下文里实测通过。
这意味着「URL 装载」与「粘贴 JS」两条产品形态**都不是空谈**。

**证据**（在真实页面里跑 `await import(...)`，探针服务器是我临时起的 127.0.0.1:8792）：

```
① 远端 ESM：   await import('http://127.0.0.1:8792/plugin.js')
   → { ok: true, name: 'cx-probe-plugin', hello: 'hello from remote plugin' }
② blob: URL：  URL.createObjectURL(new Blob([code], { type: 'text/javascript' })) → import(url)
   → { ok: true, fromBlob: 'yes', url: 'blob:http://127.0.0.1:8000/e91…' }
③ data: URL：  await import('data:text/javascript,export const fromData = 42;')
   → { ok: true, fromData: 42 }
④ 页面 CSP：   没有 <meta http-equiv="Content-Security-Policy">（页面里查不到），响应头也无 CSP
```

**几条必须一起记住的边界**：
1. **跨源要 CORS**：① 成立的前提是那台服务器回了 `Access-Control-Allow-Origin: *`。
   真实外部插件源的托管方**必须**带 CORS 头，否则浏览器直接拒 —— 这条要写进插件包的格式约定。
2. **混合内容**：本次是 http 页面，所以 http 源能 import。**部署在 HTTPS 的酒馆下，http 源会被拦**，
   那时只有 https 源可用。这条得在「粘贴 JS / blob」这条路上做兜底（blob 与 data 不受此限，是 HTTPS 场景的正解）。
3. **执行位置是酒馆页面本身**（不是沙箱 iframe）：代码与酒馆同源、同权限，**没有任何隔离**。
   这与既定口径一致（全权装载、不做权限门禁、只留来源/hash 展示；真禁网只能靠隔离档 iframe，二期）。
4. **装载时序仍未解决**（见 §2）：`import()` 拿到的是模块，而「先读 manifest 再决定装不装」需要
   一个**不执行代码就能读到的头**（JSON 头 / 先下载文本再解析 / blob 两段式），这条**没验**。

| 维度 | 评估 |
|---|---|
| 工作量 | **小**：底座已有 `PLUGIN_MANIFESTS` 聚合点与 `registerRuntimeTools` 通道，外部插件只需把「目录里的文件从哪来」换掉 |
| 风险 | **中**：① 装载即全权执行（既定口径接受）；② HTTPS 场景下 http 源不可用；③ 失败隔离要真做（见 §2 第 4 问） |
