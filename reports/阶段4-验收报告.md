### F4-1 详情 —— 已闭环（附「守卫有没有牙」的实测）

**首轮（修复前）**：唯一失败用例 `bundle_artifact.test.ts` 的
`bundle: 内联的 app JS 带上了脚本变量存储`，断言 `appJs.includes('没有可用的酒馆助手脚本变量接口')`。
根因：该字符串**在整个 `src/` 里已 0 命中**（旧版存在：`git show 85aeafe:…/storage.ts`），

**改文案是对的，断言没跟着改。** 同一测试块里`type:'global'`那条同类过期闸已被删，同一次清理漏了这条。

**Lead 的修法**（我复核过源码 `bundle_artifact.test.ts:109-112`）：不写死新文案，改成**从源码现取**：
```ts
const storageSrc = readFileSync('src/苍玄助手/core/storage.ts', 'utf8');
const phrase = /没有可用的[^'"，（）\n]*接口/.exec(storageSrc)?.[0];
assert.ok(phrase, 'core/storage.ts 里找不到…');
```

**判定：F4-1 闭环。**

#### §1.2 「守卫有没有牙」——我按 Lead 的提议实测了，结果**有保留**

Lead 说这条守卫自带第二颗牙：「改源码却忘了 build → 它立刻红」。实测**部分成立**：

| 实验（都不重新 build，只改 `storage.ts`） | 期望 | 实测 |
|---|---|---|
| 在文案**括号之后**加一个字符（`接口（…` → `接口X（…`） | 红 | **绿** ❌ 没咬住 |
| 把**两处**的 `接口` → `通道`（在正则捕获段内） | 红 | **红** ✅ 咬住了（报 `core/storage.ts 里找不到…`） |
| 只改**一处**，另一处不动 | 红 | **绿** ❌ 没咬住 |
| 还原后重跑 | 绿 | **绿** ✅ |

**原因**：正则是 `没有可用的[^'"，（）\n]*接口`，字符类**排除了 `（`**，所以它只捕获到
`没有可用的变量写入接口` 这一段（不含括号内容）；且 `storage.ts` 里该文案有**两处**
（`:821` 与 `:844`），`.exec()` 只取**第一处**。于是：
- 改动落在括号之后 → 不在捕获段内 → 看不见；
- 只改一处 → 正则可能匹配到**没改的那处** → 仍然通过。

**判定：守卫对「最常见的改法」（改文案措辞、两处一起改）是有效的**，能真正拦住「改了源码忘了 build」；
但**不是万能的**。这是**信息项，不是阻塞** —— 如实记录，供 Lead 决定是否收紧（例如：把两处一起取、
或直接断言 `appJs.includes('保存失败：')` 与源码里的出现次数一致）。

我全程只读 + **按备份逐字还原**：`storage.ts` 与备份**字节相同**，全文 `507/507` 恢复为绿，无残留。
