# 扩展迁移 · 宏系统与关键设计约束（Lead）

> 证据：ST 官方文档 `docs/SillyTavern-Docs/For_Contributors/Writing-Extensions.md:873-954`；ST 源码 `public/scripts/st-context.js:112,180-181`。

## 一、宏注册：换用新一代 `macros.register()`

**旧路（我们现在的 `registerMacroLike`）已被 ST 官方标记 deprecated：**

| | 旧 | 新 |
|---|---|---|
| 注册 | `getContext().registerMacro(name, fn)`（**已 deprecated**，未来移除） | `getContext().macros.register(name, {handler, description, category, unnamedArgs})` |
| 注销 | `getContext().unregisterMacro(name)`（**已 deprecated**） | `getContext().macros.registry.unregisterMacro(name)` |
| 别名 | — | `macros.registerAlias(from, to, {visible:true})` |

官方原文（:937）：「`registerMacro()` and `unregisterMacro()` from `getContext()` are **deprecated**. Use `macros.register()` and `macros.registry.unregisterMacro()` instead.」

**决策：扩展版直接走新 API。** 顺带解决本项目历史上「`registerMacroLike` 端到端未证实」的遗留问题——那条路本身就是要被移除的旧路，不值得再投入验证。

## 二、⚠️ 硬约束：宏 handler 必须**同步**

官方原文（:916）：「Handlers will **run synchronously**, so they can never return a `Promise` or call async actions synchronously.」

这对我们是**真实的架构约束**，因为插件宏接口长这样（`plugins/types.ts:53-60`）：

```ts
export interface PluginMacro {
  name: string;
  scopes: Array<'tavern' | 'preset'>;
  desc?: string;
  render: (data: PluginMacroContext) => string;   // ← 同步返回 string
}
```

**好消息：现有契约已经是同步的**（`render` 返回 `string` 而非 `Promise<string>`），与 ST 要求天然兼容。

**但必须在扩展版显式固化这条约束**，否则将来有人写 `async render()` 会在真机上静默失败（宏渲染成 `[object Promise]` 或空）。建议：
1. 在 `PluginMacro.render` 的类型上**保持 `string`**（不要放宽到 `string | Promise<string>`）；
2. 加**运行时守卫**：注册前检测 `render(...)` 返回值是不是 Promise，是则拒绝注册并报可读错误；
3. 加**测试断言**：内置插件的每个宏 `render` 都同步返回字符串。

**推论（设计上的取舍）**：需要「实时数据」的宏（如 `{{图片提示词}}`）只能读**底座提前缓存好的**数据（我们已有的 `rememberMacroValues` 机制正好对上），不能在宏里现查现取。这条约束要写进插件开发文档。

## 三、宏生效范围（比酒馆助手更宽）

官方（:875）：注册的宏「can be used anywhere where macro substitutions are supported, e.g. in the **character card fields, STscript commands, prompt templates**, etc.」

这比酒馆助手脚本形态更好：底座宏不再局限于「我们自己渲染的预设」，只要玩家在角色卡/预设里写 `{{宏名}}` 就能生效。**这正是「酒馆的 agent」该有的样子**——深入到酒馆自身的文本管线里。

## 四、对插件契约的连带影响

扩展版宏贡献可以**增强**（都是 ST 原生支持的，非自造）：
```ts
export interface PluginMacro {
  name: string;
  scopes: Array<'tavern' | 'preset'>;
  desc?: string;
  /** 新：ST 宏系统的分类（用于 /help 与宏列表展示） */
  category?: 'utility' | 'character' | 'chat' | 'system' | ...;
  /** 新：声明式参数（ST 支持宏带参数，如 {{宏 参数}}） */
  unnamedArgs?: Array<{ name: string; description: string }>;
  /** 保持同步 */
  render: (ctx: PluginMacroContext, args?: string[]) => string;
}
```
→ 插件宏**第一次可以带参数**了。这是原脚本形态给不了的能力。
